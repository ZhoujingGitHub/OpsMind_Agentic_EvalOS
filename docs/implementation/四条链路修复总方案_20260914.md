## 0. 设计原则（防屎山）

> **一个事实，一个来源，一次翻译。**

1. **不新增层。** 现有 27 个 LG 节点、AH 单 Agent 循环、EvalOS 评分内核**一个都不动**。
2. **只删不加。** 主要工作是**删除错误的翻译链**，不是增加兼容分支。
3. **复用已验收资产。** AH 的 `opsmind-mec-business-verification/1.0` 已经两轮通过（100 / 96.43），直接提升为公共契约，不重新发明。
4. **一次 break change。** 开发阶段，不保留旧语义、不留兼容层、不做双写。
5. **共享组件谨慎动。** `task_success` 的定义**不改**（AH 两条链路依赖它），只是不再让任何人拿它当业务健康。

## 2. 修复方案

### 阶段 0：磁盘治理（先做，不改代码，解除部署阻塞）

**顺序不可颠倒：**

1. 只读统计 `candidate_relay_requests` / `candidate_relay_nonces` 的时间分布（现场执行，本次因全表扫超时未取到）
2. 停 EvalOS 写入或在低峰窗口执行
3. `DELETE FROM candidate_relay_requests WHERE created_at < date('now','-7 days') AND status IN ('COMPLETED','FAILED','EXPIRED')`
   —— 保留 QUEUED/LEASED（在途请求）
4. `DELETE FROM candidate_relay_nonces WHERE received_at < date('now','-2 days')`
   —— nonce 只用于防重放，2 天足够；保守起见可用 7 天
5. `VACUUM`（需要等量临时空间，当前 25G 空闲够用）
6. 重新生成一份干净备份，校验可读、`ledger.valid = true`
7. **确认新备份可用后**，删除两个 18G 旧备份
8. 清理 `/opt/opsmind-evalos/releases` 只留 current + previous

**硬性禁止：**
- ❌ 不删 `ledger_entries`（37 万条审计账本，哈希链，删即失效）
- ❌ 不删 `trace_records` / `trials` / `case_versions` / `grader_runs`（真实评测证据）
- ❌ 不在拿到可用新备份前删旧备份

**长效措施：** 在 EvalOS 里加一条 relay 保留策略（默认 7 天），避免再次堆积。这是本方案里唯一"加代码"的地方，约 20 行。

## 4. 执行顺序与验收

```
阶段 0  磁盘治理               ← 先做，解除部署阻塞，不改产品代码
   ↓
阶段 1  实验室层（LG 入编制 + 补网络 + 公共业务验证）
   ↓
阶段 2  LG 层（删错误翻译链）          ← 阶段 1、2 可并行开发，必须一起部署
阶段 3  EvalOS 层（读真业务事实）
   ↓
阶段 4  AH 层（P1，可并行）
   ↓
验收：① AH→5G  →  ② LG→5G  →  ③ AH→EvalOS→5G  →  ④ LG→EvalOS→5G
      单一实验室独占串行，一轮一条，每轮封存证据 + 复位
```

### 必须覆盖的行为（阶段 2/3 的测试下限）

1. 第一个动作成功但业务未恢复 → 回调查，允许提出第二个动作
2. 某动作失败、后续动作成功、业务验证通过 → 历史失败保留，任务结果"已恢复"
3. 最后一个提案未执行 → 不得覆盖此前动作结果或任务级验证
4. 策略拒绝过时提案 → 回只读调查；安全停止仍终止
5. root_cause 能同时表达已确认局部根因与待确认问题
6. EvalOS 接收完整历史 + 唯一任务级结论，不用最后动作猜
7. 多动作不因数量本身判失败
8. **AH 两条链路不回归**（阶段 3.1 改动后必须重跑）

### 验收通过标准

| 链路 | 目标 |
|---|---|
| ① AH→5G | 业务 passed + Agent 运行正常完成 + 报告含根因 |
| ② LG→5G | 业务 passed + 允许多动作 + 任务级结论与业务事实一致 |
| ③ AH→EvalOS→5G | ≥ 92.14（不低于本次基线），15/15 硬门 |
| ④ LG→EvalOS→5G | 15/15 硬门，分数达标 |

**并且：`environment_recovery` 必须在业务真实不通时为 false。** 这是本次方案的核心验证点——用一次故意不修复的对照轮次证明评分体系有能力发现"业务没好"。
