## 五、共同合同先明确

1. 能力目录从实际注册和依赖状态产生，包含能力标识、说明、参数格式、资源类型、可用性、失败原因、操作影响和目录版本。AH 查询/使用同一目录，不维护第二份可自由漂移的白名单。
2. 扩展当前 list_data_capabilities / 公开能力合同，让 Agent 查得到本次环境；现有工具按职责复用，参数校验和采集实现同源。未知能力明确返回不支持，不能静默换名或改写用户参数。
3. 资源仍使用 identifier_domain + namespace + resource_type + resource_id；逻辑 Trial namespace 与 Linux 网络 namespace 的映射由服务端负责。新增组件由权威实验室清单扩展 Scope，经控制面传入 AH/EvalOS；Agent 不自行扩大授权。
4. 纯读取、限量主动探测、临时抓包、修复动作分别标注。普通读取复用只读入口；探测/抓包使用既有执行约束和预授权范围。绝不借 readonly 名称执行任意远端 Shell 或修改网络规则。
5. 每份结果记录资源、请求/调用、采集时间、实际覆盖、数据来源、目录/采集器版本、退出状态、截断和后续读取引用。不同工具读取同一采集物不能算多份独立血缘。
6. 请求归属和成功观测归属分开核验。失败尝试可证明请求属于当前调查，但不能伪造一份成功的实验室响应。失败和部分结果均保留，EvalOS 只对真实观测执行成功证据要求；跨 Trial 和伪造数据仍拒绝。
7. 实时数据不借用旧冻结结果。日志命中、进程存活、应用健康和业务恢复分别表述；缺失、空结果、未安装、超时、拒绝各有明确状态。
8. 继续复用现有证据存储、不可变引用和分页读取，不计划新增业务数据库或重复存储完整结果。诊断源缺失不能用产品库存或静态样例补成成功。
9. 保留本地 SDK 原生工具的自主分析能力：Agent 可编写脚本分析已授权证据，远端采集与 MCP 使用同一身份、Scope 和审计。
10. 本次公共合同遵循一个新运行口径。已有合法调用尽量通过可扩展字段保持兼容，不保留错误名称别名、静默回退或两套执行器。历史记录保持原样并按历史版本解释。

### 9.1 能力与结构验证

### 9.2 两路线抽样场景
从当前已有场景中，按不同故障机制预先固定4个样本：

| 样本 | 选择原因 | 真实模型运行 |
| --- | --- | --- |
| N2/SCTP阻断（sctp-blocked） | 覆盖本次已暴露的防火墙诊断、协议连接、修复审批、独立验证和EvalOS结算 | 直连1次 + EvalOS1次 |
| 订阅认证不一致（subscriber-key-mismatch） | 覆盖跨组件配置、订阅数据库、认证日志与终端注册调查 | 直连1次 + EvalOS1次 |
| N6路由缺失（n6-route-missing） | 覆盖UE隧道、UPF、虚拟承载、多观察点及MEC端到端路径 | 直连1次 + EvalOS1次 |
| 关键日志缺失（observability-gap） | 覆盖采集失败、证据不足、诚实不确定结论及可靠收口 | 直连1次 + EvalOS1次 |

正式抽样共8次，使用同一最终候选版本组、同一公开任务语义、由评测控制面冻结的相同场景/种子条件、产品级安全预算。样本在看结果前确定，不因失败换成容易通过的场景。
每场独立Trial与证据，逐场独占、复位、证明可用后再跑下一场。修复模式按现有冻结授权合同执行；证据不足场景诚实inconclusive，不强行修复。
其余16类场景本次不要求逐项付费模型验收。23项能力仍逐项进行不调用模型的工程与实际采集验证，包括本次4个模型样本未覆盖的DNS、MQTT、资源容量等。
