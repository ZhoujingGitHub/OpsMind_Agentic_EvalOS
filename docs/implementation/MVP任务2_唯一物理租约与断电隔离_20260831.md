# MVP任务2：唯一物理租约与断电隔离

- 日期：2026-08-31
- 状态：已完成
- 范围：只修改5G实验室外围控制和两个产品的薄适配器；未修改四套系统的调查、取证、评分、审批或动作安全核心

## 产品经理结论

真实5G实验室现在只认最底层控制器保存的一份“当前使用者”记录。LangGraph 直连、Agent+Harness 直连和 EvalOS 评测不能再各自创造一份物理占用事实，也不能同时占用实验室。

实验室主机重启、旧租约过期、租约文件损坏或首次升级状态不明确时，系统一律先进入“隔离待处理”，不会猜测旧任务可以续跑。只有执行明确复位，并逐项证明5G核心网、故障注入、转发、用户、数据网和路由恢复干净后，实验室才重新显示为空闲。

本任务没有新增数据库、调度器或常驻监督服务。

## 实际改了什么

### 一份物理租约

唯一物理租约由5G实验室最底层控制器保存，活动路径为：

`/srv/opsmind-twin/physical-lease.json`

它记录：

- 使用模式：LangGraph 直连、Agent+Harness 直连或 EvalOS 评测；
- 当前产品；
- EvalOS Trial 标识（只有评测模式才有）；
- 产品内部运行标识；
- 唯一租约标识和到期时间；
- 实验室主机本次开机标识；
- 空闲、使用中或隔离待处理状态。

两个产品原来的薄适配器现在只能读取和转交这份租约。它们仍可保留各自产品内部所需的绑定资料，但不能据此宣称自己拥有第二个物理实验室槽位。

### 明确的断电规则

- 本次开机标识与租约记录不一致：隔离；
- 使用中的租约过期：隔离；
- 租约文件损坏或无法判断：隔离；
- 复位过程中任一清洁检查失败：继续隔离；
- 只有明确执行 `recover` 并全部验证通过：恢复空闲。

正常状态查询使用轻量入口，只读取租约和开机标识，不会因为产品频繁查询而反复执行完整实验室检查。

## 真实环境验收

部署前已把5G实验室原控制器和两个产品薄适配器保存到：

`/var/backups/opsmind-twin-task2-20260831-mvp/`

备份校验值与切换前记录一致，可用于精确恢复外围文件。

新控制器首次看到旧环境时按设计进入隔离，没有自动接着运行。随后只执行了一次明确的恢复动作；恢复结果显示全部基线检查通过，包括5G核心网、故障链、流量延迟、IP转发、数据网接口、用户资料、转发规则和隔离网络。恢复后：

- 物理租约状态为空闲；
- 当前使用模式、产品、Trial 和租约均为空；
- 主机开机标识已固定记录；
- LangGraph 和 Agent+Harness 查询到的是同一份物理租约；
- 两边都显示可以申请实验室，但没有活动任务；
- 没有创建调查、Trial，没有调用 observe，也没有启动 EvalOS Runner。

本任务没有为了验证断电而真的重启共享实验室主机，因为那会无谓中断现场。开机标识变化、旧租约不得续跑和恢复前必须隔离，已经由可重复的自动测试覆盖；真实主机当前开机标识也已记录。后续若发生真实重启，同一规则会立即执行。

## 测试结果

- EvalOS 全量测试：156项通过，0项失败；
- 唯一租约、Eval管理器和旧报到网关相关专项测试：17项通过；
- LangGraph 全量测试：全部通过，1项按项目条件跳过；
- Agent+Harness 全量测试：全部通过，2项按项目条件跳过；
- 两个产品的薄适配器都覆盖了“旧调用格式必须拒绝”和“只能使用底层物理租约”的测试；
- 代码格式、Python 编译和 Git 差异检查通过。

## 部署中发现并处理的问题

Windows 首次上传脚本时带入了 Windows 换行，Linux 在执行前就明确拒绝了脚本。没有在这个错误状态下执行复位。修正为 Linux 换行、增加仓库换行规则、重新编译检查并安装后，才执行真实恢复。这说明切换门禁有效，也避免该问题以后重复出现。

## 仍保留到后续任务处理的旧外围

- 旧 Candidate Bearer/SSH 报到入口还暂时存在，但已经不再拥有物理租约事实；任务5的新签名报到通道验证通过后会一次性删除。
- 两个产品主机上可能仍有旧状态文件残留，但新控制器不再读取它们；为保留可回滚性，本任务不提前删除，任务8验收新路径后统一清理。
- LangGraph 现场仍有一个旧 systemd/Docker 双重监督残留；它不属于实验室租约，本任务没有越界处理，任务3会在应用备份后精确移除。

这些是按已批准的串行实施顺序暂留的切换保护，不是永久兼容方案；到对应任务不能删除时必须停止收口并说明原因。
