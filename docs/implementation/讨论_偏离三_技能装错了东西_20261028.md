## 0. 结论先说

**技能装错了东西：装的是模型早就会的，缺的是模型不可能会的。**

```
装了什么   14 个技能写的是 5G 教科书常识和通用调查方法     → 21 次调查里合计只被调过 4 次
缺了什么   「我们这套系统的工具怎么用、规矩是什么」         → Agent 在这上面摔了上百次跟头
           参考代码（黄金提示词点名要的第三样东西）          → 一行都没有
```

最有说服力的一条证据：**Agent 的 20 次 Bash（现场写代码）里，9 次是在跟我们自己的「结果翻页」工具较劲**，
另有 7 次在摸索怎么连上实验室的诊断通道。它的开放能力，大部分花在了替我们的工具设计「还债」上。

**而且最大的那个卡点（结果翻页，占全部工具失败的 39%）根本不是知识问题，是工具设计问题**——该改的是 MCP 工具，不是写技能。

推荐：本周**不改技能**，让本周 18 道新故障题当一次免费的测量；**本周顺手修掉翻页这个工具缺陷**；
下一轮（扩题之后）按真实卡点重写技能、配上参考代码。要你拍板的有 2 件（第 6 节）。

## 2. 为什么没被调用：两个原因，本周能把它们分开

### 原因一：考的题太窄

这 21 次调查**全是同一种故障**（SCTP 被封，基站和核心网之间的连接被防火墙拦了）。
切片、无线、MEC、容量趋势这些技能，这道题本来就用不上。

### 原因二：写的是模型已知的东西

和这道题最相关的三个技能（5G 架构与接口、核心网、IP 承载）也一次都没被调过——因为里面写的东西 DeepSeek 本来就懂。

### 本周正好能把两个原因分开

本周要跑的 3 种新故障，恰好落在另一批技能的领域里：

```
GTP-U 被封（基站到 UPF 的用户面）    → 对口技能：5G 架构与接口、核心网、IP 承载
PFCP 被封（SMF 到 UPF 的 N4 接口）   → 对口技能：5G 架构与接口、核心网
数据库进程停（签约数据那一侧）       → 对口技能：核心网（UDM）、MEC 与业务（数据库）
```

```
本周跑完后看：对口的教科书技能被调了吗？
   ├─ 被调了   → 原因一为主：只是之前没考到，技能本身还有用
   └─ 还是不调 → 原因二坐实：这些内容模型早就会，该删或合并
```

**前提是本周不改技能**——一改，就分不清是「换了题」还是「换了技能」带来的变化。

### 3.1 翻页为什么是工具设计问题，不是知识问题

**打个比方。** 去银行取号排队，号码纸上直接印着「第 8 位，柜台 3，业务：开户」。
你换了个业务（从开户换成转账），还拿着旧号码去叫号——柜员说「号不对」。
更糟的是号码纸上的字能看懂，于是有人干脆自己写一张「第 16 位」的号码纸递上去。

我们的翻页凭证就是这样一张「看得懂的号码纸」：它是能直接解开的明文结构，
里面写着偏移量、集合、指纹。所以：

```
① Agent 换了集合或过滤条件，忘了丢掉旧凭证     → 46 次失败
② Agent 看得懂凭证，干脆自己改偏移量去拼       → 9 次 Bash
```

**这不该靠写技能去教 Agent「记得丢掉旧凭证」，而是该把工具改好**：
- 凭证改成**看不懂的短编号**，Agent 没法也没必要去拼
- 换了条件还拿旧凭证时，报错里**直接给出「下一次该怎么调」的完整参数**，照抄就行

这一条按你定的判别标准（「如果没有考试，还该做吗？」）是**该做的**：真实运维里，Agent 照样要翻页。

### 3.2 黄金提示词的第三样东西：参考代码，现在是零

黄金提示词原话：「别的东西，要么是 MCP，要么是 skill 文字描述，要么是参考代码。」
现在插件目录里**只有 SKILL.md 文字文件，没有任何脚本**。

官方技能本来就支持在技能目录里放脚本，Agent 用 Bash 去跑。
3 节里那次「试了四种办法连实验室诊断通道」，如果技能里放着一段现成的调用示例，就不用现场摸索了。

## 4. 技能本该装什么（下一轮重写的方向）

**判别标准一句话：模型自己不可能知道、又反复要用的东西。** 从第 3 节的真实卡点倒推：

| 应该补的 | 来自哪个真实卡点 | 形式 |
|---|---|---|
| 本系统的结果怎么读、怎么翻页、证据编号怎么找回 | 翻页失败 46 次（工具改好后仍需一段说明） | 技能文字 |
| 提动作方案的规矩：先读能力目录、用精确资源引用、参数在合同范围内 | 提动作方案失败 10 次 | 已有，但要让 Agent 在该用的时候想得到——描述要改，或在提动作方案那个工具的说明里直接点名 |
| 实验室诊断通道怎么用（只读诊断命令的用法） | 7 次 Bash 摸索 | 技能文字 + **参考脚本** |
| 实验室什么时候算「已绑定」、没绑定时能查什么 | 5 次「没有准备好的实验」 | 技能文字 |
| 本网的部署事实：哪些网元同机部署、共用一张防火墙表 | 考场就在这上面数错过（同一条规则被当成 6 条） | 技能文字 |

**应该删或合并的**：①类 7 个教科书技能、②类 7 个和提示词重复的方法技能——等本周测量结果出来再定删哪些。

**必须守住的边界**：**不能**把实验室注入故障的细节写进技能（比如注入用的防火墙规则叫什么）。
那等于把答案写进产品，和「考场不能自造词表」「提示词不能写阅卷口径」是同一个错。判别标准还是那一条：**「如果根本没有这场考试，这条还该写吗？」**

## 5. 这一条在面试里怎么讲

这是三处偏离里**最适合拿去面试的一条**，因为它有真实数据、有反直觉的结论、有明确的下一步：

> 「我量了 21 次真实调查：21 个技能里 15 个从没被调用，因为它们写的是模型早就懂的 5G 教科书知识。
> 反过来看 Agent 真正卡在哪：117 次工具失败里，39% 是我们自己的翻页工具设计得不好；
> 它 20 次现场写代码，将近一半是在跟这个工具较劲。
> 所以技能的价值不在于教模型通用知识，而在于装模型不可能知道的东西——我们系统自己的规矩和工具用法。
> 而有些坑根本不该用技能去补，该直接把工具改好。」

这和 `面试/2026-09-10_为什么要给Agent公司规章制度部门分工和业务信息.md` 讲的是同一个道理，这次有了真实数据撑着。
