## 0. 结论先说

**你说得对：系统应该有切换模型的入口，而且现在的写死已经是一颗定时炸弹。**
但「升级到 V4.1」有一个反直觉的事实要先摆出来：

```
线上实际在答题的，已经是 V4.1 了——只是我们填的还是旧名字。
```

DeepSeek 官方价格页原话：旧名字 `deepseek-v4-flash`「仍可调用，但对应模型已下线」，
这类请求由 **DeepSeek-V4.1-Flash-1017** 来答，按 Flash 的价格计费；官方建议改用新名字 `deepseek-flash`。

由此牵出三个新发现：

```
① 名字骗了我们   09-14 以后的考试实际用的是 V4.1，所有记录写的都还是 V4
② 定时炸弹       旧名字是「临时」转接，没给截止日期；AH 和 LG 都把旧名字写死了，
                 哪天转接一停，两个产品当场全部调不通，而且只能改代码发版才能恢复
③ 对比不对等     LG（V1）在四个关键步骤用的是更强的 V4-Pro，AH（V2）从头到尾只用 Flash
                 ——过去所有「V1 对 V2」的比较，模型都不是同一个
```

**推荐的做法**：给 AH 加一套「**模型档案**」，分三层入口（第 3 节）；本周两个产品都把模型名改成 `deepseek-flash`。
要你拍板的有 3 件（第 5 节）。

## 1. 先把事实摆清楚：我们到底一直在用哪个模型

### 1.1 官方时间线（来自 DeepSeek 官方变更日志）

| 日期 | 官方发生了什么 |
|---|---|
| 08-13 | V4-Pro 正式发布（`deepseek-v4-pro`）；思考强度开放 low / high / max |
| 08-16 | 开始分时计价，空闲时段半价 |
| **09-10** | **V4.1 Flash 发布；V4 Flash 退役；旧名字 `deepseek-v4-flash`「临时」转到 V4.1 Flash**；Flash 降价 |
| 09-14 | V4-Pro 在这之后继续提供，计费不变 |
| **10-17** | **V4.1 Flash 再升级到 V4.1-Flash-1017**，名字仍叫 `deepseek-flash`，价格不变 |

### 1.2 对到我们自己的考试上

```
08-14       M1.5 合成题 90 场（面试里的「领先 13.45 分」）  ← V4 Flash
09-05~07    两路线验收                                      ← V4 Flash
──────── 09-10  V4 Flash 下线，旧名字被临时转到 V4.1 ────────
09-14~20    AH 21 次真实调查 + 考场 8 道题                   ← 实际是 V4.1 Flash（09-10 版）
                                                              记录里写的却是 V4
──────── 10-17  V4.1 Flash 升到 1017 版，名字不变 ────────
本周要跑的 18 道                                             ← V4.1-Flash-1017
                                                              （不管我们改不改名字，都是它）
```

**这里有个要紧的推论**：本周新跑的题，就算我们什么都不改，答题的模型也已经和 09-20 那批不一样了（09-10 版 → 10-17 版）。
所以「为了和以前可比，先别动模型」这个理由，**其实已经不成立了**——官方在 10-17 已经替我们换过了。

### 1.3 为什么我们一直没发现

AH 每次调查都会记下用量，线上最近一次（`inv-6be21847094b`）记的是：

```
用的模型：["deepseek-v4-flash"]      ← 这是我们请求时填的名字，不是实际答题的版本
输入 170,293 token，输出 80,961 token
```

DeepSeek 只是把我们填的名字原样写回来，**实际是哪个版本在答，记录里看不出来**。
打个比方：你一直在同一家店点「招牌拉面」，店家某天换了厨师和配方，菜单上的名字没变，小票上印的也还是「招牌拉面」。

## 2. 三个新发现，逐个说

### 2.1 名字骗了我们

**影响到哪**：考场的冻结清单、验收记录、面试材料，凡是 09-14 之后的成绩，写的都是「V4 Flash」，实际是 V4.1 Flash。

**怎么处理**（这一条不需要拍板，是纠错）：
- 历史存证**不动**（那是「当时就是这么记的」的凭据）
- 在验收记录和面试材料里加订正说明：「09-14 起实际答题的是 V4.1 Flash，10-17 起是 V4.1-Flash-1017」
- 以后每次考试，除了记「请求时填的名字」，还要记下「官方当天把这个名字映射到哪个版本」

### 2.2 「临时转接」是一颗定时炸弹

官方原话是「**临时**」转接，「对应模型**已下线**」，**没有给截止日期**。而两个产品都把旧名字写死了：

| 产品 | 写死在哪 | 换别的名字会怎样 |
|---|---|---|
| AH | `config.py:299-306` | 不是 `deepseek-v4-flash` 就**拒绝启动** |
| AH | `main.py`「我用的是什么模型」接口 | 把 `deepseek-v4-flash` 当成文字直接返回，不读实际配置 |
| LG | `settings.py:49`、`contracts/eval.py:27` | 类型上只允许 `deepseek-v4-flash` 这一个值 |

```
哪天 DeepSeek 停止转接旧名字
        ↓
AH、LG 的每一次调用都报错 → 所有调查失败
        ↓
想换成新名字 → 代码不允许 → 只能改代码、测试、发版、重新登记考生
```

这正是你说的「应该有灵活切换模型的入口」要解决的问题。

### 2.3 V1 和 V2 用的模型不对等

线上 LG 容器的配置里有两项：

```
OPSMIND_MODEL_ID=deepseek-v4-flash            ← 平常的步骤用 Flash
OPSMIND_REASONING_MODEL_ID=deepseek-v4-pro    ← 「深思」步骤用 Pro
```

LG 代码里规定，**修订、裁决、定稿、提动作方案**这四个阶段用 Pro，其余用 Flash（`deepseek.py:25-30`、`:684`）。
AH 则从头到尾只用 Flash。

| | AH（V2） | LG（V1） |
|---|---|---|
| 平常的步骤 | Flash | Flash |
| 关键的四个判断步骤 | Flash | **Pro**（价格约是 Flash 的 4.5 倍） |

**这对面试故事的影响**：过去所有「V1 和 V2 谁更强」的说法，模型都没有控制住。
LG 在最关键的判断上用了更强的模型——现在两边在真实实验室里打平（各 3/4），**不能说明架构谁好**，
因为有可能是「LG 的架构差一些，但被更强的模型补回来了」，也可能不是。**待确认，要用同模型对照才能说清。**

不过这也是一个**可以讲的真实优点**：流程图架构天然可以「按步骤挑模型」，关键步骤用贵的、普通步骤用便宜的。
AH 要做到同样的事，也需要第 3 节的档案机制。

## 3. 推荐的设计：「模型档案」+ 三层入口

### 3.1 什么是模型档案

一份档案说清楚「用哪家、哪个模型、怎么连、多少钱、验没验过」。拿现在线上的 DeepSeek 举例（全是官方页面上的真实值）：

| 档案字段 | 例子 | 说明 |
|---|---|---|
| 档案名 | `deepseek-flash-v4.1` | 给人看的名字 |
| 厂商 | DeepSeek | — |
| Anthropic 格式地址 | `https://api.deepseek.com/anthropic` | 黄金提示词要求：只用 Anthropic 格式 |
| 模型名 | `deepseek-flash` | 官方当前推荐名 |
| 官方当前映射版本 | DeepSeek-V4.1-Flash-1017 | 记录用，解决 2.1 节「名字骗人」 |
| 思考强度 | high | 官方支持 low / high / max |
| 单价（元/百万 token） | 输入 1～2、缓存命中 0.02～0.04、输出 4～8（空闲/高峰） | 用来算真实花费，顺带修好「AH 自报花费是虚数」 |
| 密钥位置 | 指向服务器上的密钥文件，不是密钥本身 | LG 已经是这么做的（`file:///run/secrets/deepseek_api_key`） |
| 认证状态 | 已认证 / 待体检 / 停用 | 只有已认证的档案能被选中 |

### 3.2 三层入口

```
第①层  档案清单（运维）
       新增一个模型 = 在服务器上放好密钥文件 + 在清单里加一条档案
       ↓ 新档案默认是「待体检」，不能被选
第②层  管理员切换默认档案
       做法照搬现成的「切换工作模式」接口：只有管理员能切、每次切换留审计记录、
       只能在「已认证」的档案里选、只影响之后新开的调查，进行中的调查不受影响
       ↓
第③层  单次调查指定档案
       提交调查时可以指定用哪份档案（不指定就用默认）；这份档案会被冻结进本次调查的运行合同和审计记录
       → 每一次调查都能说清「用的是哪个模型、哪个版本、花了多少钱」
```

**为什么第③层做得到、又不用重启**：AH 每开一次调查，都会单独启动一个 Claude Agent SDK 会话，
连接地址、模型名、密钥都是这个会话自己的配置（`harness.py:1499`）。所以按调查切换模型，在技术上是顺手的事。

**第③层顺带打开的能力**：考场以后可以拿**同一个 AH、换不同模型**来考——不只比架构，也能比模型。
（考场那边要能在派题时传档案，那是下一轮的事，本周只把 AH 这边的口子做好。）

### 3.3 新档案怎么上线

```
放好密钥、加档案（待体检）
        ↓
体检：用这家的 Anthropic 格式地址，验证工具调用、流式输出、思考模式、按需找工具都正常
        ↓
真跑一次完整调查（AH 现成就有这个认证：去翻记录，看这个模型有没有用 SDK 真跑通过一次带工具调用的调查）
        ↓
标为「已认证」→ 管理员才能选它
```

Kimi、GLM、Qwen 的 Anthropic 格式地址网上都能查到，但都只核实到「待确认」（见核查文档 4.2 节），
**而且我们手上没有这三家的密钥**。所以本周档案清单里只放 DeepSeek，另外三家等你有密钥后按上面三步上线。

### 3.4 和黄金提示词对一下

| 黄金提示词的要求 | 这个设计 |
|---|---|
| 核心 Agent 必须是 Claude Agent SDK | 不动。换模型只是换 SDK 会话的地址、模型名和密钥 |
| 国产模型只需改地址，用 Anthropic 格式 | 档案里只收 Anthropic 格式地址 |
| 地址弄不清就上网查，不要用 OpenAI 格式 | 新档案必须先过体检，不靠记忆、不靠教程 |

### 3.5 一个刻意不做的地方：不在网页上输入密钥

把密钥贴进网页表单，密钥会经过浏览器、网络、接口日志，泄露面大很多。
所以第②层的入口只负责「选哪份档案」，**密钥一律由运维放到服务器的密钥文件里**，档案里只记文件位置。

## 5. 要你拍板的 3 件事

### 问题 15（改写）｜切换模型的入口做到哪一层

| 选项 | 做法 | 本周工作量 |
|---|---|---|
| **甲（推荐）** | 后端三层都做（档案清单、管理员切换默认、单次调查指定）；工作台页面本周**只显示**当前用的是哪份档案、哪个版本，切换走管理员接口 | 约半天到一天 |
| 乙 | 甲 + 工作台加一个切换下拉框 | 再多约半天；前端要重新构建、重新上线 |
| 丙 | 只做第①层：档案清单 + 重启服务生效 | 约两小时；但没有「入口」，只是不再写死 |

### 问题 17｜模型名改成官方推荐的 `deepseek-flash`

| 选项 | 做法 | 影响 |
|---|---|---|
| **甲（推荐）** | AH、LG 都改成 `deepseek-flash`，考场冻结清单同步 | **实际答题的模型不变**（本来就是 V4.1-Flash-1017），只是不再依赖「临时转接」 |
| 乙 | 继续用旧名字 | 转接哪天停了，两个产品当场全挂 |

### 问题 18｜V1、V2 模型不对等怎么处理

| 选项 | 做法 | 影响 |
|---|---|---|
| **甲（推荐）** | 本周两边各保持现在的用法（LG 关键四步用 Pro，AH 全程 Flash），但成绩单和面试材料**如实写明**；下一轮用新的切换入口做一组「两边同模型」的对照 | 本周不增加费用；面试时能说清「模型没控制住，下一步怎么控制」 |

| 丙 | 本周就让两边同模型：AH 也改用 Pro | AH 每道题的模型费用约涨到 3.7 倍（按 `inv-6be21847094b` 的 17 万输入、8.1 万输出估算，高峰时段、全部不命中缓存的最贵情况：Flash 约 1 元，Pro 约 3.7 元）；需要多充值 |
