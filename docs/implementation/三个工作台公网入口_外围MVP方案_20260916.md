## 1. 演示窗口模型（本版的核心姿态变化）

**入口默认是关闭的。** `access.conf` 常态写着 `deny all;`；演示前一条命令开、演示完一条命令关。

这样攻击面**只在演示窗口内存在**，成本为零。产品机上有 19.8 GB 生产库、
MySQL/Postgres/Redis 和调用 5G 实验室的通道；让它 7×24 对公网可达，收益只有"随时能打开页面"，
而演示是可预约的。

三层防护叠起来，任何一层单独失效都不会导致数据泄露：

```
第 0 层  安全组 443（只在需要时存在，删规则秒级生效）
第 1 层  access.conf 总开关（常态 deny all；演示时清空）
第 2 层  nginx Basic 认证 + limit_req（口令三套互不通用）
第 3 层  应用自己的登录与权限（AH 邮箱+口令+租户；LG 用户名+口令+JWT，超管还要填理由）
```

**EvalOS 那台按同样姿态收口**：本轮已改成默认 `deny all;`。

> **2026-09-16 执行时纠正**：本节原先写"三个机器对机器入口（relay、presence、judge）都不受
> 总开关影响"，这**不准确**，HANDOFF 里也有同样的错误说法。逐行核对线上配置后：
> `/api/candidate-relay/` 与 `/api/candidate-presence` 两个确实既无 `auth_basic` 也不含
> 开关文件；但 **`/api/trials/.../judge` 是带 `auth_basic` 和 `include access.conf` 的**。
>
> 关掉页面入口仍然**不会打断链路③④**，但理由不是"judge 免认证"，而是
> **评测内核走机内 `127.0.0.1:3000` 调 judge，不经 nginx**（access 日志当前窗口 0 次命中）。
> 关闭后的实测：25 秒内仍有 92 次 relay 认领全部 200、presence 全部 202。
> 如果将来 judge 需要从机外驱动，这条要重新评估。

## 3. U1 / U2 查证结果

### U1：续期停 nginx 不会丢 relay 请求 —— 安全

`/srv/opsmind-eval-bridge/relay-worker.py`（190 行）：

- 主循环 `run()` 捕获 `HTTPError / URLError / TimeoutError / RuntimeError`，
  打日志 + 睡 ≤5 秒 + **继续循环**，不退出不丢
- 认领任务是 `POST /api/candidate-relay/<ref>/claim`，带 **`lease_ms: 60000`**（60 秒租约）
- 最坏情况：claim 成功但回报 completion 时 nginx 正好停 → 该请求 60 秒租约过期后**可被重新认领**
- systemd 侧另有 `Restart=always` / `RestartSec=2`

**结论**：秒级停机不丢请求，最坏是延迟。续期 timer 仍定低峰。

顺带确证：第 123 行用 `ssl.create_default_context()`，**证书校验是开着的**——
所以证书过期确实会断 relay，第 5 节那件事是真的。

### U2：`sslip.io` 不在公共后缀列表里 —— 有额度风险，且带出一个新问题

实测下载 publicsuffix.org 官方列表（16477 行）：**整个列表里没有 "sslip"**，
同类的 `nip.io` 也不在。

后果：Let's Encrypt 按"注册域名"算额度，`sslip.io` 不在列表里意味着
**全世界所有 `*.sslip.io` 用户共享同一个额度**。签发可能因别人用光而失败。
（LE 当前额度的确切数字我不能从记忆断言，所以下面用试签来验证，不用推算。）

**由此带出的新问题（v1 没想到）**：EvalOS 那张证书 10 月 14 日的自动续期**也吃同一个额度**。

> **所以续期 timer 必须在失败时告警，不能静默失败。**
> 否则等于把"没人续证书"换成"续了但失败了也没人知道"，照样在 11-13 挂掉。

应对：
1. **先用 `--staging` 试签**（不消耗生产额度），通过再签正式
2. **一张 SAN 证书覆盖 `lg.` 与 `ah.` 两个名字 = 一次签发**，比两张省一半额度
3. 真撞额度就换 **ZeroSSL / BuyPass**（acme.sh 的 `--server` 支持），或临时自签 + 演示机信任
4. 续期脚本包一层：非零退出就写系统日志 + 落一个哨兵文件，
   并把 `openssl x509 -checkend` 加进 `tools/check-balance.sh` 那类日常只读检查

## 4. 配置

**http 层**，`/etc/nginx/conf.d/opsmind-consoles-limit.conf`：

```nginx
limit_req_zone $binary_remote_addr zone=opsmind_lg:10m rate=20r/s;
limit_req_zone $binary_remote_addr zone=opsmind_ah:10m rate=20r/s;
```

两个考生**各自一个 zone**。共用会让一方的使用挤掉另一方的配额，
那是把两个本应独立可比的系统耦合起来。

**LG**，`/etc/nginx/sites-available/opsmind-lg`：

```nginx
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name lg.114-55-40-170.sslip.io;

    ssl_certificate     /etc/nginx/ssl/opsmind-product/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/opsmind-product/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;

    location / {
        include /etc/nginx/opsmind-lg-access.conf;   # 常态 deny all；演示时清空
        auth_basic "OpsMind LangGraph";
        auth_basic_user_file /etc/nginx/opsmind-lg.htpasswd;
        limit_req zone=opsmind_lg burst=50 nodelay;

        proxy_pass http://127.0.0.1:8081;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 5s;
        proxy_read_timeout 600s;                     # AH/LG 调查是长任务，别卡在 300s 边界上
    }
}
```

**AH**，`/etc/nginx/sites-available/opsmind-ah`：

```nginx
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name ah.114-55-40-170.sslip.io;

    ssl_certificate     /etc/nginx/ssl/opsmind-product/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/opsmind-product/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    include /etc/nginx/opsmind-ah-access.conf;       # 放 server 级，两个 location 共用
    auth_basic "OpsMind Agent Harness";
    auth_basic_user_file /etc/nginx/opsmind-ah.htpasswd;

    location / {
        root /srv/opsmind-ah-web;
        try_files $uri $uri/ /index.html;            # BrowserRouter 深链接刷新不 404
        limit_req zone=opsmind_ah burst=50 nodelay;
    }

    location /v2/ {
        limit_req zone=opsmind_ah burst=50 nodelay;
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 5s;
        proxy_read_timeout 600s;
    }
}
```

AH 的 `dist/index.html` 用**绝对路径**引用 `/assets/index.css` 与 `/assets/index.js`，
所以它必须占一个主机名的根路径——这正是用子域而不是路径前缀的原因
（子域可用性已在服务器侧 `getent hosts` 实测：`lg.` 与 `ah.` 都解析到 `114.55.40.170`）。

**不开 80。** acme.sh 用 TLS-ALPN-01（EvalOS 实测 `Le_Webroot='alpn'`），签发与续期只需 443；
80 在大陆公网会被阿里云 ICP 拦截页替换，对浏览器也没用。

**和 EvalOS 的结构差异**：EvalOS 留了三个免认证 location（relay、presence、judge）；
产品机**一个都不需要**——relay 在产品机上是**出站**方向（产品 API 是本地回环）。

**写操作全部放行。** 发起故障根因调查、人工审批、切租户都照常——完整平台演示的要求。

## 5. 前置：EvalOS 证书续期（最急，与开放解耦）

查证结果：root `crontab` 空、`/etc/cron.d/` 无相关行、无 acme/opsmind 的 systemd timer、
`/etc/letsencrypt/live` 不存在（**certbot 什么都没管**）、真正签证书的是 acme.sh
（`Le_Webroot='alpn'`，`Le_NextRenewTimeStr='2026-10-14T01:23:04Z'`）、
`renew-evalos-cert.sh` 只存在于 `releases/*/` 里，**没有任何调度会调用它**。

证书 `2026-11-13 09:29:22 GMT` 到期 → relay TLS 校验失败 → **链路③④ 断**。
`certbot.timer` 每天在跑、看起来一切正常，这正是它危险的地方。

修法：装到 `/usr/local/sbin/`，配 systemd timer 每天一次（acme.sh 自判续期窗口，未到空跑，
天然幂等）；**外面包一层失败告警**（见第 3 节 U2）；停掉误导人的 `certbot.timer`。

## 8. 演示操作手册（开 / 关）

写成两个幂等脚本，经云助手调用：

```
演示前：三个 access.conf 清空 → nginx -t && systemctl reload nginx → 浏览器确认能进
演示后：三个 access.conf 写回 deny all; → nginx -t && systemctl reload nginx → 确认 403
```

**演示前置准备**（实用提醒）：

- **演示前先在浏览器里登录好三套 Basic 认证**。共享屏幕时当场输口令既暴露"这里有个口令框"，
  也可能被看到
- **地址必须 `https://`**。漏打会得到"连接被拒绝"（因为不开 80）
- **本机 `curl` 测不出可达性**：这台机是 TUN 模式代理全局接管、出口在东京，
  同一地址 curl 报握手失败而浏览器正常。**判断可达性一律用浏览器**（RUNBOOK 坑 12）
- 演示期间不要同时跑链路验收：实验室只有一个物理租约，会互斥
  （按产品经理判断当前阶段不会并发，**不做机制，只作一条人的规则**）

## 9. 明确不做，但要记住

1. **不要因为"应用自己有登录"就撤掉 nginx 的 Basic 认证。**
   AH 与 LG 都**没有关掉** FastAPI 自带的 `/docs`、`/redoc`、`/openapi.json`；
   AH 更把这三个显式写进了免鉴权白名单
   （`services/agent-service/src/opsmind_agent/main.py:383` 的 `public_paths`）。
   撤掉 Basic 认证等于公开整套接口说明书（含发起调查、审批的参数结构）。
   本 MVP **不额外加 404 规则**——`location /` 上的 Basic 认证已经盖住它们。
   轻薄的代价就是这条依赖必须写下来。
2. **AH 与 LG 的认证端点都没有登录失败锁定**（已 grep 确认）。属产品侧待办，要改应用代码。
3. **AH 控制台的写入端点包含 `/v2/admin/users`、`/v2/admin/roles`、
   `/v2/remediation/kill-switches`、`/v2/remediation/policy-packs`** ——建账号、改熔断策略。
   LG 没有这两类。演示期按完整平台放行，但**这是 AH 入口比 LG 入口更需要看住口令的原因**。
4. **不在产品机装 node 工具链**（所以前端只能本机构建 + Git 投递）。
5. **宿主机第二层防火墙**：安全组是唯一边界。加固项，演示窗口模型已大幅降低其必要性。
6. **Git 里 `infra/nginx/opsmind-evalos.conf` 是 09-15 加认证之前的旧版**，要一起修。
7. **外部爬虫曾请求过账本里真实存在的 trial URL**，泄漏源未查清（HANDOFF 遗留第 3 条）。
   演示窗口模型让这条风险大幅缩小——入口常态关闭，爬虫扫不到。
8. **nginx 日志**：确认 Ubuntu 默认 logrotate 覆盖到新 vhost（11 GB 余量下，401 会刷日志）。

## 10. 需要产品经理知情的一条合规事项

技术上已实证 443 不被 ICP 拦截页替换（EvalOS 正在跑）。但 `sslip.io` **未备案**，

**但这是合规判断，不是技术判断**，需要你知情后决定。演示窗口模型也顺带降低了这条的暴露面。
