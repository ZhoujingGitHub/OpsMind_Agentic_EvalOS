## 4. 三处偏离，一处一个例子

### 4.1 交报告前「必须先调用某个技能」，是写死的

```
Agent 调查完，调用「交报告」
        ↓
代码检查：这次调查里调用过 report-workorder（报告工单）这个技能吗？
        ↓
没调过 → 打回，错误写着 required_skill_not_completed（必需的技能没完成）
```

位置：`tools.py:265-266`，09-02 提交 `25b5aa5` 加的。
线上证据：21 次调查里，report-workorder 这个技能**每次都被调了一遍**（21/21），
而其余 20 个技能加起来一共只被调了 9 次——它被调，是因为代码逼着调，不是 Agent 自己觉得需要。

**为什么算偏离**：黄金提示词要求「代码只管权限、预算、安全、证据、审计」。
「先做 A 再做 B」是流程，不属于这五样。打个比方：公司要求**交上来的报告必须有领导签字栏、数据必须有出处**，
这是验收标准；但规定**写报告之前必须先翻一遍某本手册**，就是在管员工怎么干活了。

**而真正要保住的东西，代码里已经有了**：同一个检查函数接下来就逐条校验——
每条建议是不是指向领先假设、引用的证据是不是本次采到的、有没有把无关建议混进来
（`tools.py:270` 往后）。所以去掉「必须调技能」这一条，报告质量的门槛一点不降。

### 4.2 模型地址和模型名被焊死在 DeepSeek

```
【黄金提示词】 换模型 = 只改地址和密钥（DeepSeek / Kimi / GLM / Qwen 都有 Anthropic 格式地址）
【现在】       地址不是 https://api.deepseek.com/anthropic → 服务拒绝启动
               模型不是 deepseek-v4-flash               → 服务拒绝启动
```

位置：`config.py:299-306`。写死的原因是考试要可比（两个考生必须用同一个模型），
这个理由在考场上成立，但它写在了**产品**里，于是产品失去了换模型的能力。

**另一处跟着失真**：SDK 按 Claude 的价目表算花费，而实际调用的是 DeepSeek，
所以 AH 自报的花费是虚数（09-24 已查出，评估文档问题 7 已覆盖）。

### 4.3 技能挂对了，但大多没被用到

| 技能 | 09-14 以来被调用次数 |
|---|---|
| report-workorder（报告工单） | 21（被代码强制，见 4.1） |
| remediation-safety（修复安全） | 4 |
| open-world-investigation（开放世界调查） | 2 |
| ran-radio、blast-radius-and-ownership、evidence-hypothesis-reasoning | 各 1 |
| **其余 15 个**（5G 架构与接口、核心网、承载、切片、MEC、主动探测……） | **0** |

21 个技能合计约 2 万字符，平均一个约 1 千字符，偏薄。
**这不违反架构**——挂载方式完全按官方文档；问题出在「技能写得够不够有用、描述能不能让 Agent 想到用它」。
原因待确认，可能是描述不够具体，也可能是这些故障用 MCP 直接查就够了。
它和面试讲的「领域知识封装成 Skill」直接相关，面试官问「技能实际用了多少」时要能如实回答。
