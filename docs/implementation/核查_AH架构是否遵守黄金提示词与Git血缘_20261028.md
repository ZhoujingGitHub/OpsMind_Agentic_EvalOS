## 4. 三处偏离，用人话细看（10-28 补量后改写）

先看全貌——三处偏离的**性质完全不同**，不能用一种办法处理：

```
偏离一  规矩多立了一条      → 删掉这条规矩（小改，本周做）
偏离二  门被焊死了          → 把焊点换成「认证名单」（中改，本周做，线上行为不变）
偏离三  技能里装错了东西    → 先如实记下，扩题之后再重写（下一轮做）
```

### 4.1 偏离一：交报告前「必须先调用报告工单技能」

**打个比方。** 一家餐厅墙上贴着「每道菜出锅前，厨师必须先翻一遍菜谱」，
出菜口另有一位质检员，逐盘检查「配菜和主菜对不对得上」。

**这条规矩写在两个地方：**

```
① 提示词第 126 行：「提交正式报告前必须实际完成 report-workorder 技能……自审」   ← 墙上的告示
② 代码 tools.py:265：交报告时检查有没有调过这个技能，没调过就打回           ← 门口的保安
```

**线上真实发生了什么**（09-14 以来 21 次真实调查，从线上库逐次数出来的）：

| 量什么 | 结果 | 人话 |
|---|---|---|
| 这个技能被调用 | 21 次里 21 次 | 厨师每次都翻了菜谱 |
| 调用时机 | 21 次全都在**第一次交报告之前** | 是看了墙上告示自己翻的，不是被保安拦回去才翻 |
| 因为「没调技能」被打回 | **0 次** | 门口那位保安一次都没拦过人 |
| 报告被打回（有记录的） | **18 次** | 质检员照样退回了 18 盘菜 |
| 打回的原因 | 几乎全是「建议引用的证据，和它要支撑的那个假设对不上」 | 退菜全是因为配菜和主菜对不上 |
| 交报告的调用 | 21 次调查共 49 次；只有 1 次调查一次就交上了 | — |

**这说明三件事：**

1. 代码里那道检查是**多余的保险**：提示词已经让 Agent 每次都自审了，代码那一层从来没起过作用
2. 自审**没能拦住**真正常见的错误：21 次都自审了，仍有 18 次因为「证据没绑到对的假设上」被退回
3. 真正把住质量的是**内容检查**（`tools.py:270` 往后逐条核对建议、假设、证据的对应关系），它一直在起作用

**来历**：09-01 提交 `9a16627` 加了「用已有技能做建议自审」；第二天 `25b5aa5` 改成「必须完成，否则打回」。

**为什么说它偏离了黄金提示词**：黄金提示词让代码只管权限、预算、安全、证据、审计。
「先做 A 才能做 B」是在规定工作顺序，不属于这五样。**技能本身没问题**——
报告工单技能有 6.6 千字节，写的全是本项目报告的规矩，是 21 个技能里最有用的一个；问题只出在那个「必须」。

**改了会怎样（问题 14 选甲）**：

```
【现在】 提示词说「必须」 + 代码检查有没有调过 → 没调就打回
【以后】 提示词说「可以用它自审」             → 用不用 Agent 自己定
         内容检查一条不动                     → 报告门槛不降
```

**要如实说的风险**：去掉「必须」后，Agent 可能有时不自审，第一次交报告就被打回的次数可能上升；
每多打回一次，就多一轮模型调用（具体多花多少钱，待本周真跑后量）。本周 18 道新题跑完就能看出来，明显变差再议。

### 4.2 偏离二：模型地址和模型名被焊死在 DeepSeek

**打个比方。** 一辆车出厂时把油箱口焊成只认一家加油站的油枪：安全、省心，但想换一家加油站，就得开回厂里改车。

**焊点在两个地方：**

```
① config.py:299-306   地址不是 https://api.deepseek.com/anthropic → 服务拒绝启动
                      模型不是 deepseek-v4-flash               → 服务拒绝启动
② main.py「我用的是什么模型」接口   直接把 "deepseek-v4-flash" 当成文字写死，不读实际配置
                                    ← 只要放开第①处，这里就会报假信息，所以要一起改
```

**来历**：08-10 重建那次（`588536b`）一起写进去的。当时有两个合理的理由：
考试要求两个考生用同一个模型；DeepSeek 的 Anthropic 接口做过兼容性体检——
代码注释写着，Claude Code 遇到非 Anthropic 的地址会自动关掉「按需找工具」，是体检通过后才手动打开的。

**为什么不能真的「只改地址」**：各家对 Anthropic 格式的兼容程度不一样，
工具调用、思考模式、按需找工具都可能有差别。所以「换模型」实际是两步：**先体检，再上线**。

**产品里其实已经有一半现成的东西**：AH 有一个「模型认证」，它去翻历史记录，
看这个模型是不是**真的用 SDK 跑通过一次带工具调用的调查**——这是按事实认证，不是按名字认证。

**几个国产模型的 Anthropic 格式地址**（10-28 上网核实，没有凭记忆写）：

| 厂商 | 地址 | 核实到什么程度 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/anthropic` | ✅ 线上正在用 |
| Kimi（月之暗面） | `https://api.moonshot.ai/anthropic` | 多个来源一致；国内用的 `.cn` 版本**没找到官方确认，待确认** |
| GLM（智谱） | `https://open.bigmodel.cn/api/anthropic` | 第三方教程一致，**没找到官方页面**；有人反映能不能用和所购套餐有关，**待确认** |
| Qwen（阿里云百炼） | `https://dashscope.aliyuncs.com/apps/anthropic` | 阿里云官方文档有，但另一页官方文档给的是带工作空间号的地址，**以控制台为准，待确认** |

**改了会怎样（问题 15 选甲，比上一版说得更具体）**：

```
【现在】 代码里写死一个地址、一个模型名
【以后】 一份「认证名单」：每一项 = 地址 + 模型名 + 体检结果
         新厂商要用真密钥跑一遍体检、真跑通一次调查，才能进名单
         「我用的是什么模型」接口改成如实读配置
```

**本周名单里只有 DeepSeek 一家**——另外三家既没有密钥，也没体检过，不该凭网上的地址就放进去。
所以本周线上行为**完全不变**，变的只是「以后换模型不用改代码」。

**考试可比性怎么保住**：考场登记考生时已经会读「我用的是什么模型」这个接口、把模型记下来；
但开考检查会不会因为模型对不上而拦下，**我没找到对应代码，待确认**——执行时补一条测试把它钉住。

**顺带**：SDK 按 Claude 的价目表算花费，实际调的是 DeepSeek，所以 AH 自报的花费是虚数——这是评估文档问题 7，已经在修。

### 4.3 偏离三：21 个技能里 15 个从没被调用

**打个比方。** 给一位老医生配了 21 本手册。他天天翻的只有一本：本院自己写的《病历书写规范》。
另外 15 本是《人体解剖学入门》一类的教科书——他早就会了，不会去翻。

**先看数据：**

| 技能 | 大小 | 09-14 以来被调用 |
|---|---|---|
| report-workorder（报告工单） | **6,605 字节** | 21 |
| remediation-safety（修复安全） | 762 字节 | 4 |
| open-world-investigation（开放世界调查） | 747 字节 | 2 |
| ran-radio、blast-radius-and-ownership、evidence-hypothesis-reasoning | 539 ~ 700 字节 | 各 1 |
| **其余 15 个** | 492 ~ 1,581 字节 | **0** |

**原因一：考的题太窄，很多技能本来就用不上。**
这 21 次调查**全是同一种故障**——SCTP 被封（基站和核心网之间的连接被防火墙拦了）：
13 次是一字不差的同一份症状描述，另外 8 次是同一故障换了 4 种考法、各考两遍。
切片、MEC、无线、容量趋势这些技能，这道题根本用不上。**所以「15 个没被调用」，一部分只是因为没考到。**

**原因二：和这道题最相关的技能也没人翻——因为里面写的是模型早就知道的东西。**
这道题最该用到的三个技能是「5G 架构与接口」「核心网控制面与用户面」「IP 承载」，一次都没被调过。
打开看，「5G 架构与接口」的正文是这样的：

> N2 连接基站和 AMF；N3 连接基站和 UPF；N4 连接 SMF 和 UPF，用 PFCP 协议……

这是教科书第一章，DeepSeek 本来就懂。**技能里装的东西，模型不缺。**

**技能真正该装什么**：模型不可能事先知道的**本地知识**。用本项目真实存在的例子：

| 例子 | 为什么模型不可能自己知道 |
|---|---|
| 沙箱里有一个只读诊断命令 `opsmind-readonly-diagnostic`，以及它的用法 | 真实调查里，Agent 是自己翻目录、读帮助才找到的（第 2 节那个例子） |
| 本网哪些网元部署在同一台机器上、共用同一张防火墙表 | 考场判分就在这上面数错过：同一条规则被当成 6 条 |
| 同一份抓包反复查询，不算多份独立证据 | 报告工单技能里已经写了，这正是它好用的原因 |

**必须守住的边界**：**不能**把实验室注入故障的细节（比如注入用的那条防火墙规则叫什么）写进技能——
那等于把答案写进产品，和「考场不能自造词表」「提示词不能写阅卷口径」是同一个错。
判别标准还是你定的那一条：**「如果根本没有这场考试，这条还该写吗？」**

**改了会怎样（问题 16 选甲）**：本周不动。理由有两个：
一是改技能会改变 Agent 的行为，本周新跑的 18 道题就没法和 09-20 那 8 道放在一起比；
二是现在只考过一种故障，改完也测不出技能到底有没有变好用——要等第四批扩题之后，才能在多种故障上诚实地测。
本周只把「21 个技能用到 6 个、原因是装了教科书知识」如实写进面试材料，下一轮单独立项重写。

> **这一条在面试里是加分项**：「我量了 21 次真实调查，发现 15 个技能从没被调用，因为里面写的是模型早就知道的东西。
> 技能的价值在于装模型不知道的东西——公司的规章、本网的部署、过去踩过的坑。」
> 这和 `面试/2026-09-10_为什么要给Agent公司规章制度部门分工和业务信息.md` 讲的是同一个道理，而这次有真实数据撑着。

### （顺带）提示词里写进了阅卷口径

提示词第 123 行有「算没有指准」「会被判为没有定位到根因」「那是倒豆子」。
这不属于架构问题，是考试规则渗进了产品，09-24 已列为评估文档的问题 4（推荐删掉）。
