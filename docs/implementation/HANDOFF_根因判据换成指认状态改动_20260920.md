## 5. 新判据的完整设计

### 5.1 真值 = 实验室注入故障时那条命令的参数

实验室每次造故障都是一条很具体的命令，**标准答案一直就在那里**：

```
sctp-blocked        iptables -A OPSMIND_TWIN_IN -p sctp --dport 38412 -j DROP
pfcp-blocked        iptables -A OPSMIND_TWIN_IN -p udp  --dport 8805  -j DROP
gtpu-blocked        iptables -A OPSMIND_TWIN_IN -p udp  --dport 2152  -j DROP
dns-blocked         iptables -A OPSMIND_TWIN_FWD -s 10.45.0.0/16 -p udp --dport 53 -j DROP
amf-process-down    systemctl stop open5gs-amfd      （smf/upf/nrf/mongodb 同型）
n6-route-missing    ip route del 10.46.0.0/24
```

出处：`infra/twin/opsmind_twinctl.py` 的 `inject_fault()`（约 717–742 行）与
`copy_active_configs()`（约 560–576 行）。

### 5.2 真值写成「考生看得见的样子」

真值不能写成注入命令的形态（`--dport`），要写成**观测记录里的字段名**，
否则又会重演今天的错。两者的对应已经逐条核过（见第 6 节）。

题库里每个场景新增一份 `faultDeltas`：

```
每一处改动 = {
   观测种类      network_policy / process_state / routes / subscriber
   identify      考生必须指出的字段 → 值（字段名与值都照观测原样）
   state         present（这处东西存在且是错的） | absent（这处东西不见了）
   injectedBy    实验室真正执行的那条命令（只用于一条一致性测试，不参与判定）
}
```

真实例子（`sctp-blocked`）：

```
observation : network_policy
identify    : chain=OPSMIND_TWIN_IN, protocol=sctp, destination_port=38412, target=DROP
state       : present
injectedBy  : ["iptables","-A","OPSMIND_TWIN_IN","-p","sctp","--dport","38412","-j","DROP"]
```

### 5.3 考生要交什么

在**领先假设**上加一个字段（两个产品各写各的，不共用代码）：

```
root_cause_state_claims: [
  { evidence_id: "<它自己引用的那条证据编号>",
    fields: { chain: "OPSMIND_TWIN_IN", protocol: "sctp",
              destination_port: "38412", target: "DROP" },
    state: "present" }        // 默认 present，缺失的东西填 absent
]
```

**`fields` 里的每一个字段名和值，都必须是它自己观测里原样出现过的。** 不发任何词表。

### 5.4 判定规则

```
对每一条 claim：
   state=present → 在它引用的那条证据里，找字段全部匹配 claim.fields 的记录
                   ★ 必须恰好命中一条 ★（命中 0 条 = 指不明；命中多条 = 没指准）
   state=absent  → 不做查找，claim.fields 直接参与比对

对每一处真值改动：如果有某条 claim 解析出的记录包含它 identify 里的全部字段值，
                 且 state 相同，就算命中

精确命中  每一处改动都被命中，且没有多余的 claim，条数相等  → 40/40，过门
部分命中  命中了一部分，或有多余的 claim                    → 20/40，不过门
未命中    一处都没命中                                      → 0/40，不过门
题库没标  该题不适用（见 5.6）                              → 这一维退出分母
```

**「恰好命中一条」是核心。** 它同时解决了三件事：

- 考生只填 `protocol=sctp` → 可能命中多条 → 判"没指准"，不用另写规则
- 隐藏噪声题那条干扰规则（udp/9999）→ 指错了字段就对不上，自动判出来
- pfcp（8805）与 gtpu（2152）自动分开，不用手工加限定字段

### 5.5 打分与门

| | 改成 |
|---|---|
| 根因这一维 40 分 | 全部给「指认那处改动」，**取消原来的 实体定位 10 分子项**（改动本身已经含了对象） |
| 门（能动手的题） | 状态对 + 只改一处 + **实验室独立复测业务从断到通** |
| 门（不能动手的题：只诊断 / 安全停止） | 状态对 + 没有虚假因果主张（指认不能是"命中了但指错"） |
| 证据质量 30 / 处置质量 30 | **不动** |

> 依据：ABC 清单把「状态修改类任务」单列为一组（O.g），真值就是状态；
> 「结果当门、说法给分」对应 AIOps2025 的加权口径（定位 40 / 类型 40 / 可解释 10 / 效率 10）。
> **「真值直接用注入参数」这一条是我们自己的**——成立是因为我们拥有那个注入器，
> 通用 RCA 基准没有这个条件，别写成业界做法。

amf / smf / upf / nrf / mongodb-process-down / gnb-process-crash /
