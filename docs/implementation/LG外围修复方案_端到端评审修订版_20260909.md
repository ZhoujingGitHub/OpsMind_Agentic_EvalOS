# LG 外围修复方案：端到端评审修订版

日期：2026-09-09。性质：架构评审与实施规格草案，不是代码交付或验收通过声明。用户本轮要求客观深审方案，未据此启动修复、部署或Trial。

## 最新实施授权：LG修复，EvalOS仅候选登记与LG结果接收

2026-09-09 用户已批准开始实施，并在澄清现有登记入口没有热更新、旧接收计算无法表达先失败后恢复后，明确授权：“还是允许仅更新候选登记及 LG 结果接收逻辑（AH代码、评分权重、历史记录不动）”。此项最新授权覆盖下节历史边界，允许为这两项加载必要配置和部署；不扩大到AH、评分权重或历史记录。以下四块按本节范围实施。每轮真实验收后均停止，与用户讨论结果，不自动继续下一轮。

已在隔离数据库复现旧动作目录升级到6ab时的不可变定义冲突，正在通过新动作定义版本修复，禁止覆盖旧目录。当前实施进展不代表最终候选已部署或验收。

## 历史用户边界：仅修LG，AH与EvalOS均不修改（已被上节限定授权修订）

用户进一步明确“不要写成屎山，力求外围架构轻薄稳定，不修改AH和EvalOS”。本节覆盖下文涉及EvalOS改动的旧提议；当前不修改AH/EvalOS代码、配置、部署和评分语义。下文D块与验收矩阵中的EvalOS接收修订、共享解释改动及对应发布不再列入获准实施范围。这里只更新方案文档，不修改产品。

四块缩减为：A从现有LG状态生成清楚一致的模型上下文；B在LG内部统一动作定义、当前动作和完整历史；C在LG现有Graph中补齐安全再调查；D只处理LG发布、升级回退和对既有EvalOS合同的兼容验证。不增加新存储、新Agent、第二调度循环或新发布平台；替代逻辑应移除旧执行解释，历史仍可读。

普通只读取证失败允许Agent换工具、换合法参数继续调查，不为每次调查调用增加审批。外部修复失败则核实真实副作用；新修复重新审批，旧修复历史保留。仅禁止范围/权限明确拒绝后的绕行访问、未知写结果盲重试等行为。

本轮复审不能无条件承诺仅改LG即可兑现原方案全部语义：

- 当前EvalOS接收的action_lifecycle可由LG提供明确当前动作，全部历史继续在原事件/账本中提供，优先维持现有公开字段，不能随意breaking change外部合同。
- 既有EvalOS的productRepairProgress要求全部attempted动作均成功且验证有效。因此先真实修复失败、后成功的调查，可能仍被评为未恢复。LG不能删失败事件、把失败改名或伪造恢复来绕过；该限制属于既有评测合同，不擅自修改。
- 本地最新登记仍锁定LG c8a0d41及其镜像摘要，规范登记函数要求实测版本和冻结版本一致。新LG代码不能冒用旧身份证。本次不擅自改EvalOS配置；正式运行第二链路前须确认既有EvalOS是否有用户允许使用的原生候选登记入口。尚未核实能在完全不变更EvalOS配置/部署的条件下登记新版本，因此“新LG两链路可验收”的发布依赖仍未闭合。

评审结论调整为：LG内部收敛方向可继续完善，当前方案尚不能称满足最新边界的完整可部署版本。先只读澄清候选登记方式和既有评测语义的影响，再形成最终实施清单；不以无依据承诺或越权改EvalOS消除矛盾。仍不自动启动修复、部署或验收，每轮真实验收后停止讨论的要求不变。

## 评审结论

第一版四块方向成立，但不能原样实施。主要遗漏是：让调查支持第二次动作，会同时影响动作状态、审批入口、公开API、页面、EvalOS接收、回滚、归档与清场。仅接回一条Graph边会制造新的半闭环。修订仍保留四块，以现有状态、账本、事件、网关和发布入口实现，不增加平台层。

目标限定为受控单实验室、串行运行的LG直连与LG经EvalOS两条链路。一次调查可有多个按序决策/提案；每项外部动作仍单独授权，不允许并发修复、跨租户或跨Trial执行。单Case通过不宣称所有故障、并发或客户生产场景均已验收。

## 一、证据与新发现

| 问题 | 已核实事实 | 对方案的影响 |
|---|---|---|
| 单动作对外投影 | LG api/app.py约1113行按事件正序取第一个action_id，只返回一个action_lifecycle；EvalOS product-connectors-v5.mjs约1482行据此构造审批；LG页面也读取这个字段 | 新动作必须有明确当前动作引用，完整历史独立可读；API、页面、EvalOS一并改 |
| 当前动作状态混在调查状态 | GraphState中proposed_action、approval、execution_ticket、action_attempt、verification等为单组字段 | 返回调查前必须关闭旧动作上下文；不能只清一个status而留下旧授权或结果 |
| 恢复节点直接结束 | reopen_and_escalate随后进入finalize_and_learn，原代码实际设置human_takeover | 恢复流程要区分非终态与真终态，否则Worker可能提前归档/移交实验室 |
| 回滚范围过大 | LG专属网关rollback_fault调用reset_baseline、清空实验室changes并重新inject_fault | 不得用于多动作连续调查；不能把重置整题当成某一次动作的逆操作 |
| 恢复结果聚合不支持先失败后成功 | EvalOS product-action-events.mjs约95行要求所有attempted动作均executed且effective才设置recovery_verified | 若支持恢复循环，需要版本化接收语义；保留全部失败事实，最终恢复依据独立现场证据，不是把失败删掉或选最后一个成功事件 |
| 工具结果重读与新观察未充分区分 | tool_attempt_disposition拒绝同环境已完成调用；环境指纹来自绑定指纹/connector_profile | 同Trial现场变化后不能继续把旧测量当新测量，必须明确测量身份、观察时间及覆盖 |
| 启动目录不可变 | SqlSafetyLedger同步比较同版本完整JSON；6ab新说明字段影响仍保留旧版本的条目 | 先隔离复现启动失败，版本化修复，禁止覆盖历史目录；API/worker并发同步也要验证 |
| 运行无限期与授权有限期不同 | 模型/框架人工累计限制已取消；共享控制器现有物理租约上限7200秒 | 不能宣称所有外部权限无限有效；正式运行前核实租约/停止与恢复策略，不偷偷延长权限或删除租约保护 |

上述是代码行为或明确结构风险，不把尚未发生的第二动作错误说成三轮历史失败的直接原因。历史原始证据不改。

## 二、四块实施规格

### A. 单一上下文投影，避免制造第二份状态

继续以现有GraphState/Checkpoint保存调查工作状态、原证据库保存事实、MySQL动作账本保存授权与执行事实。一个纯构造入口生成模型可见上下文，不自行查远端、不写状态、不作业务决策、不缓存另一份权威信息。

所有阶段共享同一任务/Scope/能力定义/证据引用/未决问题/当前动作事实。阶段职责和可调用权限单独传入；能力定义相同，不要求把全部原始证据、所有提示词重复塞给每个模型。领域指导按实际阶段需要选取，不能把决策必需的动作效果只留在取证阶段。

完整原始目标单独保留；事实、工具返回和历史文本作为数据，不能扩大权限或修改系统职责。默认清理凭据；模型不能读取隐藏场景、Case答案或评分器内容。先按真实环境与Scope筛选能力，不向模型宣传当前无权使用的对象。

未决假设、缺口及必要证据引用不得用最后N项静默丢弃。正文可分页，模型必须知道未展示什么及如何取回；只读档案续读与对变化现场重新测量明确区分。模型API实际请求做合同测试，不能只测构造函数的中间对象。

补证机会保留为描述性索引：查过某工具/某类证据不推断问题解决；无法确认参数/目标/时间覆盖时标未知，必要时删除重复维护的机会推断。不得新建自动补证规划器。

### B. 一份动作定义、当前动作引用与不可变动作历史

沿用protocol-actions.json和现有注册器，声明准确效果、限制、参数、允许目标及真实回滚能力。定义由发布版本冻结，运行时结合Scope和连接器健康派生可用视图。只有说明同源不够，需用实际网关翻译/效果验证证明实现遵守定义。

提案依现有证据引用说明适用性；安全规则验证可客观判断的范围、版本、参数、权限、快照和票据，不伪装成能证明所有根因的规则引擎。不新增评审Agent，不硬编码具体故障答案。

新增提案使用新动作身份；重试同一次外部请求保持同一身份并查回执，不能换ID躲避幂等。当前动作由一个显式引用确定，不取第一个/最后一个事件猜测。审批幂等身份包含调查、动作、提案版本或摘要，批准必须对应当前待批准提案与有效现场快照。

完整动作历史继续来自既有MySQL账本和追加事件；对外提供当前动作和历史动作引用/分页读取。Graph只持有当前动作所需状态和历史引用，不复制一套动作账本。LG页面、审批API、Product E2E及EvalOS同步使用新合同。旧合同仅用于历史只读展示，不保留两条新任务执行路径。

回滚明确拆开：产品只允许撤销特定已执行动作；实验室管理方才负责结束后的清场。旧reset_baseline+inject_fault不作为动作回滚入口继续使用。动作精确回滚应保存所改字段/规则的执行前后事实并核对未被其他变更覆盖，不能影响别的动作。无法提供这种保证时明确rollback_supported=false，并在执行前按安全策略处理，不等失败后才发现。需要回滚保障却无此能力的动作禁止执行。本版不建立通用全系统快照恢复平台。

### C. 单一调查循环与显式安全恢复边界

保留Flash/Pro分工及动态工具选择，修改现有恢复节点和边。动作结果写入原账本后转为新观察供原复核阶段使用。Agent判断继续观察、形成新的独立提案、完成或请求人工。不得把命名为reopened的事件直接当作已恢复调查。

| 情况 | 系统处理 | Agent仍可决定 |
|---|---|---|
| 执行前明确拒绝、经核实未改现场 | 关闭本动作授权链，记录拒绝原因，回原调查阶段 | 补证、新提案或停止；不能盲重试同一被禁动作 |
| 动作执行后无效但状态已知 | 按已批准的安全边界处理；需要回滚则先精确回滚并验证 | 安全条件满足后继续调查；不能把无效自动当成无副作用 |
| 通信中断、结果未知 | 保留原请求ID，查询回执和现场，冻结新写操作 | 有权限时只读核实；不能重发另一项写操作掩盖未知状态 |
| 已验证回滚成功 | 留存动作与回滚完整事实，形成新的现场观察 | 继续调查或停止 |
| 回滚失败、权限撤销、租约失效 | 保持安全冻结/人工接管，不清除阻断标记 | 不擅自继续受限访问 |
| 运维停止 | 停止新工作；取消等待，核实在途写入，保全检查点/账本/归档与清场交接 | 不自动重启任务 |

“复核/恢复中”必须是非终态，不能设置human_takeover/completed后再循环。旧动作的批准、票据、claim、rollout、验证、回滚和路由状态成组关闭；账本历史不删除。旧快照和旧证据可以保留为历史，但不能冒充新动作前提或动作后验证。紧急停止/权限撤销状态不可随新动作清空。

一个调查只允许一个实际执行所有者。重启、重复审批、重复轮询、任务重投递、动作完成但本地未记账都必须幂等；恢复依据持久记录，不依赖进程内变量。新增恢复版本不能接续不兼容旧Checkpoint或授权。

取消累计模型/工具/Token额度和框架步数上限的要求保留。仍存在的草稿两次修正即结束、工具固定重复次数等行为限制需逐项处理或明确保留原因，不能宣称全部取消而漏查；一般格式纠错不硬塞新任务上限，确定性程序/版本错误则交运维而不是无限请求模型。

物理租约有效期是外部授权，不是推理预算。当前控制器7200秒且本轮未确认有安全续租入口。此修订不擅自改共享控制器；期限到达后无权继续访问，必须保全并明确暂停/接管。若产品要求同一Trial跨越期限持续运行，必须先另行设计管理方续租和断线失效机制；它是公开未闭合的长期运行能力，不能用改时钟、超长TTL或隐式复位解决。当前两条串行验收应在现有有效授权内进行，不能承诺无限期外部执行。

### D. 从产品交付到评测、归档和发布全部闭合

对外分别提供诊断状态、当前待办动作、完整动作历史、最终业务观察和调查终态。不以任一动作成功证明整题成功，不因一次历史失败永久否定后续有证据的恢复；失败仍参加安全/变更次数等原规则判定。

EvalOS第四块必须从“尽量只登记”修订为“必要的LG新合同接收与状态解释”：审批当前动作、连续消费事件、识别非终态恢复，最终恢复依据授权范围内、末次相关变更后有效的独立现场观察。不能简单将every改some、只选最后成功动作，或删除失败事件来抬分。评分权重、通过线和历史成绩不改。新解释是显式版本化的评测接收语义变化，必须在首次真实验收前冻结并测试；不能声称评测解释完全不变。

优先在LG版本接收路径完成变化；确需调整共享事件解释时，旧AH行为逐项回归，AH代码/服务不修改。共享验收案例至少覆盖先失败后成功、先成功后再次破坏、成功后回滚、无动作但已归档四种，防止恢复状态误报。

归档、产品终态和实验室清场各自有唯一责任方：单动作结束不触发整题清场；产品最终现场观察先固定，完整历史/用量/报告归档后交接；外部管理方/EvalOS执行清场并验证。异常终态仍保留证据与故障原因，不能因缺成功档案永久挂起或将清场恢复算产品修复。清场失败则隔离，不开放下一轮。

发布绑定LG源码/镜像、网关程序/动作定义摘要、Graph/State/公开合同、数据库版本、EvalOS接收版本与共享控制器版本。沿既有脚本和发布记录补齐核验，不新增发布控制平台。跨服务器通过阻止新任务准入、分步安装、整套回读后开放实现，不宣称原子切换。失败回退到事先验证的兼容组合；回退也失败时保持准入关闭并报出真实状态，不能宣称已恢复。

先在隔离旧数据中验证目录版本升级、API/worker同时启动、重启重复同步和回退读新数据库。只添加必要迁移，终态历史与原文档保留。旧main不提前推进；仍使用原LG/EvalOS候选分支收口，不合入废弃分支。

## 三、防止越修越重的硬边界

1. 一份能力定义、一个上下文构造入口、一个当前动作引用、原有动作账本、原有调查循环、原有发布入口。
2. 新函数只做一种职责；上下文构造不调用远端、不作路由；网关不推理；评分接收不替Agent补结论；模型不管理权限。
3. 替换旧逻辑时删除新任务路径中的旧解释，不长期维持多套兼容分支。历史只读兼容与执行兼容分开。
4. 不另建统一大框架、知识调度器、自动故障树、Agent评审队伍或第二份事件存储。
5. 改动以端到端约定为单位审查，不以文件数量、测试数量或代码行数承诺质量。扩大范围必须有实际链路依赖证据。
6. 保留必要的安全和权限边界，不通过取消幂等、审批、独立验证或租约来减少代码。

## 四、实施前必须通过的最小验收矩阵

| 场景 | 必须证明 |
|---|---|
| 相同状态进入六个模型阶段 | 任务/Scope/能力与事实引用一致，只有职责/调用权限不同；实测最终模型请求 |
| 多参数与多时点观察 | 旧测量不冒充新现场；未决问题及反证可定位和续读 |
| 第一次动作拒绝，第二次新提案 | 页面和EvalOS审批第二次准确提案，旧票据不生效，历史完整 |
| 第一次有效，第二次失败或回滚 | 不抹掉第一次动作；最终恢复由当前独立现场证据决定 |
| 写入成功但回执丢失/进程崩溃 | 同一请求不重复写，恢复后对账，不签发逃逸重复的动作 |
| 等待审批时重启/权限收回 | 不串任务、不复用过期批准，阻断状态不被清除 |
| 未知写入、错误回滚、租约失效、运维停止 | 不再发新写入；状态与清场责任明确；不能提前成功归档 |
| 工具数据夹带指令/越界目标 | 内容仅作为数据，不改变系统指令、权限、Scope或调用目的地 |
| 旧数据库升级与API/worker并发启动 | 目录版本不冲突，历史不变，支持计划中的应用回退 |
| 网关/应用任一步安装失败 | 整套兼容组合恢复或诚实保持关闭，禁止混版开考 |
| LG原生事件至EvalOS最终记录 | 当前动作正确、完整历史、独立恢复证据、失败与费用不丢失，旧AH回归保持 |
| 两条真实链路 | 同一最终LG候选，受控修复、独立业务恢复、报告与评分一致、正常清场 |

假模型用于验证上述确定性工程边界，明确是离线测试；最终两条必须真实模型、真实协议实验室。离线模拟通过不能代替真实验收；真实失败也不能倒改单项规则使其通过。

## 五、执行顺序与停止规则

先完善动作/结果合同与单一权威来源，再调整上下文与恢复路径，再同步页面/EvalOS，最后做升级/故障注入验证。全部四块成套冻结后才部署一次完整候选。

先LG直连一轮，完成最终取证及清场后无论成功失败均停止，与用户讨论；用户决定继续后，再跑同候选LG经EvalOS一轮，再停止。若期间改代码，较早轮次不能称最终版本完整验收。涉及共享接收语义的最终AH回归同样遵守逐轮停止要求。

两条修复目标是恢复注册、会话和公开任务业务，且符合冻结安全/证据/建议要求；不是只让流程能结束。未经两条实际验收通过，不合main、不打正式生产标签。该方案不保证模型每次给出正确结论，也不保证具体分钟内通过；工程边界必须先确定性验证，减少用真实模型排查基础接线错误。

本次评审结论：第一版不宜直接实施；本修订版可作为下一步实施讨论基线。长期超租约运行能力仍是明确独立边界，不以两条串行验收通过宣称该能力已完成。
