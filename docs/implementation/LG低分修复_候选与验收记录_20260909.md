## 五类修复

1. **动作目录提前可见。** LG 六个已有模型阶段都接收当前连接器筛选后的真实 ActionCatalog。未配置、无匹配动作、有匹配动作明确区分，输入摘要、版本、动作类型和连接器记录到轨迹。目录可见不授予执行权。
2. **工具与来源补齐。** 使用 LG 自己的只读数据仓库、结果存储和历史调查仓库，新增实际注册的实体发现、精确实体、网元状态、切片 QoS、业务路径、已有探针、指标、授权子图、显式诊断集合、历史调查及能力发现。租户、资源、服务、类型、时间和分页参数实际参与查询；不自动切源，不把空结果变成健康证明。历史调查仅作为历史线索。结果续取保留原始时间、质量、失败与来源，不通过分页重新“认证”。
3. **症状与因果分级。** Evidence Gate 5.1.0 要求明确对象、机制和完整有效引用，区分 confirmed、probable、insufficient。缺失引用、未解决反证、阻断缺口或同证据上的开放替代机制不能被静默删去。真实模型响应解析器保留新字段，缺失的阻断列表不自动补成空列表，错误引用格式不变成“无反证”。需要复核时复用已有假设裁决路径；未获得因果确认只安全停止，不再输出 root_cause_confirmed。
4. **报告和接收结论一致。** 最终根因与 API 结论取自 Gate 接受的假设陈述，最终报告不能另写一个未经审查的根因；报告必须引用全部接受的结论假设。草稿只能保留为明确标注的未验证判断。新增 LG 原生观测来源上下文，EvalOS 只在匹配 Trial、资源范围、工具来源、时间、质量和覆盖时解释客观观测；不向考生回填评分关键词，不伪造 AH receipt。
5. **诊断与恢复建议分开。** EvalOS grader `5.6.0`、建议契约 `1.2`。confirmed/probable 诊断即使业务 outcome 为 inconclusive，也可按证据、前提、验证、风险与自审判断建议；unknown/缺失诊断仍拒绝修复建议。任务成功与根因得分不因此被抬高。LG 接收器从 Gate 取诊断层级，不再用任务结果标签代替诊断。

冻结评分摘要：`sha256:6008db27446fd454015ae1f3872f4a4ebb231f4d60ca54f9a81cf29e699941b1`。摘要覆盖 grader 与证据解释源码，经 LF 规范化；两个当前配置及架构检查已同步。数据库中旧实验设计、旧 grader 与旧分数不回写。
