### 根因判对了

## 一个容易看错的地方：门说 probable，结论却是 confirmed

链路② 的门 `status = probable`，但 `conclusion_level = confirmed`。这不矛盾。

**LG 的确认是按「因」算的，不是按「整次调查」算的。**
`builder.py` 那段注释写得很清楚：已确认的机制照样发布，未决的问题并排列出。

```
门的 status            = 调查级档位（判据顺序里 PROBABLE 排在 CONFIRMED 之前，天生保守）
confirmed_conclusion   = 这一条因果机制是否已确认  ← 非空
   ↓
conclusion_level       = confirmed      ← 下游（含考场）读的是这个
root_cause             = 已填            ← 不再是 null
```

这段代码本身就是 **09-16 链路④ 那个缺陷的修复**：
当时门批准的 probable 结论**没有结构化字段可落**，只能写进一个散文字段、
`root_cause` 留 `null`，于是所有下游都看成"没有根因"。现在档位跟着结论一起发布。

## 两处必须如实说明的事

### 1. F5 的第二根杆只算了四个维度中的四个，缺的那一维明说了

AH 的参考档位是按 LG 五个判据里的**四个**算的：
`cited_evidence_all_exist` / `has_substantive_evidence` /
`leading_hypotheses_supported` / `no_blocking_gaps` 都真算，
但 `causal_mechanism_checked` **写死为 `false`**。

原因：AH 把因果机制写在 `cause` 的自由文本里，没有独立字段可判，
而 LG 有 `causal_confirmation` 这个独立判据。

**这不是偷偷少算**——这个标记就在门的输出里，谁读都看得见。
且 `reference_enforced=false`，它只用来量"自评跟证据贴不贴"，不夺权。

### 2. AH 的报告打回循环没有专用上限（本轮不改）

`tools.py` 的 `contract_errors` 分支直接 `raise`，没有计数器；
紧邻的"延后"分支却有 `MAX_REPORT_DEFERRALS = 2`。报告可被打回任意多次，每次烧一个模型调用。

但真实风险和 LG 差一个量级，原因是预算：

| | 循环上限 | 预算保险丝 | 实际风险 |
|---|---|---|---|
| **AH** 报告打回 | 无 | `max_model_calls=256`、`max_tool_calls=1024`、`7200s` | 浪费预算，跑不飞 |
| **LG** 草案改写（改前） | 无 | **逐项都是 `null`** | 真的会无限转，上次撞了 `GraphRecursionError` |

所以护栏① 打在 LG 上是对的：**LG 没有任何预算天花板，结构性上限是它唯一的刹车。**

**本轮不动 AH 这一条**——它是新发现，不在修复文档范围内，
应与挂起的护栏③（给开发期预算一个默认 `max_model_calls`）一并讨论。
参考值：链路① 51 次、链路② 42 次、链路③ 45 次模型调用。

链路① 实测被打回 1 次（`R1/R3:evidence_not_bound_to_target_hypothesis`：
推荐项引用了没绑定到目标假设的证据），第二版通过。
结合此前 20 次样本里的 11/20，**这个循环平时是收敛的**。
