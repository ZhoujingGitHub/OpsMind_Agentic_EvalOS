# MVP任务5：统一签名报到与正确 Readiness

- 日期：2026-09-01
- 状态：已完成
- 范围：两个产品、EvalOS 和5G实验室之间的状态报到、开考前检查、版本身份和旧外围通道清理；未创建 Trial，未启动 Runner

## 产品经理结论

两个 OpsMind 现在各自拿自己的“数字工牌”，周期告诉 EvalOS：我是谁、运行哪一版、数据库是哪一版、我具备哪些公开能力。EvalOS 只认最近180秒内、签名正确的工牌，不把心跳长期写进数据库。

能不能开考只有一套判断：产品的短期签名报到，加5G实验室最底层唯一物理租约。旧 Candidate Observation SSH 观察员不再作为第二个监督者，旧账号、网关和凭据已经删除。

最终连续两次公开检查中，Agent+Harness 和 LangGraph 都显示“可以参加资格试运行”；5G实验室保持空闲，没有创建 Trial。任务6、7、8按产品经理要求未开始。

## 1. 这一步要解决什么

- 消除“产品自己说健康、旧观察员再说一次、EvalOS又保存一份”的多重事实源；
- 避免 EvalOS 在实验室尚未准备前就要求一个不可能存在的 Trial 绑定；
- 保证真正调用模型前，产品、Trial、租约、环境、开机标识和数据库版本必须精确一致；
- 两套产品不能共用机器身份，旧报到不能在重启后继续冒充有效；
- 一次性删除旧 Bearer/SSH 活动入口，不保留隐蔽兼容双轨。

## 2. 实际改了什么

### 一个简单报到入口

- 复用 EvalOS 现有 Control API 的 `/api/candidate-presence`，没有新建微服务、数据库、队列或网关平台；
- Agent+Harness 与 LangGraph 使用完全不同的 Ed25519 私钥签名；EvalOS只保存公钥；
- 报到只含产品编号、版本、数据库版本、能力、状态、时间和随机数，不含调查内容、密码或实验室答案；
- EvalOS仅在进程内保留180秒，重启后必须等待新报到；随机数防止旧消息重放。

### 正确的两阶段检查

- 准备实验室前：确认产品版本/数据库/身份/能力正确，并确认实验室空闲；此时不要求 Trial 绑定；
- 实验室准备后、模型调用前：再次核对确切 Trial、租约、环境、产品、数据库和开机标识；任何一项不一致都阻断；
- 任务5只真实验收了前置检查。绑定后检查由测试覆盖，真实 Trial 留到任务6、7，不能写成已经跑过。

### 删除旧双轨

- EvalOS 旧 Bearer/SSH Candidate Observation 网关代码已经删除；
- 5G实验室上的旧观察账号、授权、sudo入口和网关已经删除；
- 两套产品上的旧 Candidate Observation 密钥、证明文件和会话文件已经删除；
- 产品核心里的只读诊断工具和模型可见结果能力仍保留，因为它们属于产品调查能力，不是旧外围监督通道。

### 版本和回滚

- Agent+Harness 当前版本：`2de18e8dfbb3`，上一版：`6d1c3c3b1601`，数据库仍为 `017_native_run_context_budget`；
- LangGraph 当前版本：`6a43ac7cb0f2`，上一版：`561ed9530ae5`，数据库仍为 `20260828_0011`；
- EvalOS 当前版本：`m31-20260901-f90ae61281`；正式480 Trial仍关闭；
- 应用回滚只切应用版本，不自动回滚数据库。

## 3. 哪些核心明确没动

- Agent+Harness 的 Claude Agent SDK 单 Agent、DeepSeek、MCP、Skills、ToolSearch、原生工具、Harness、Evidence、报告、预算和动作安全；
- LangGraph 的 Graph、双模型、MCP、Evidence Gate、Checkpoint、Knowledge、业务数据库语义、审批和动作安全；
- EvalOS 的真实 Trial 隔离、预算、盲身份、Twin 管理、完整 Trace、Ledger、确定性代码评分和 AI 评测；
- 5G实验室的 Open5GS、UERANSIM、PCAP 和最底层控制器语义。

Agent+Harness 仅补充了一句已有事实的公开声明：工具结果不会静默截断；模型能看到是否截断，并可自主继续分页。286项 Agent 测试通过。它没有改变模型看到结果或自主调查的方式。

## 4. 用什么证据证明成功

### 自动测试

- EvalOS 158项后端测试通过；
- EvalOS 7项前端测试通过；
- Adapter、能力保护、架构、安全、前端语法和正式构建全部通过；
- Agent+Harness 286项服务测试通过；
- 签名测试使用真实 Ed25519 私钥在产品容器内签名并自验证，不是伪造夹具。

### 产品报到

- Agent+Harness 报到版本：`2de18e8dfbb3`，数据库：`017_native_run_context_budget`；
- LangGraph 报到版本：`6a43ac7cb0f2`，数据库：`20260828_0011`；
- 两套产品的签名、公钥、随机数和预期版本完全独立；
- EvalOS连续两次读取都显示两套产品 `ready=true`、`formal_ready=true`、状态为“可以参加资格试运行”。

### 开考条件

- 两套产品版本指纹一致；
- 三角色身份分离且符合最小权限；
- 两套产品都公开自己的最大资源，限制只作安全熔断；
- Token、耗时、调用次数和费用只记录、不影响评分；
- Agent+Harness 与 LangGraph 都公开支持 `opsmind-model-visible-result/1.0`，并明确 `silent_truncation=false`；
- readiness唯一权威为 `evalos_signed_candidate_presence`，不再读取旧 Candidate Observation 作为第二套 Twin 判断。

### 实验室状态

- 最终物理租约 `status=idle`；
- 产品、Trial、运行标识、租约和到期时间均为空；
- `recovery_required=false`，当前开机标识与租约记录一致；
- 本任务没有 prepare、reset、observe、调查或 Trial。

### 清理

- 删除本地一次性私钥副本和约273MB任务5临时包；
- 删除产品服务器约146MB临时构建/上传目录和旧观察凭据；
- 删除5G实验室的一次性备份/上传文件和旧观察入口；
- 删除4个失败/中间镜像、3个 LangGraph 中间发布目录及对应失效白名单入口；
- 当前版和上一版回滚均保留且健康。

## 5. 还剩什么风险

- 任务5只证明“开考前可以安全判断”，没有证明真实 EvalOS Trial 能完成；这必须由任务6、7各跑一个资格 Trial验证。
- LangGraph 的实验室连接曾出现一次短暂 `degraded`，下一次读取恢复 `healthy`，随后连续检查通过。它更像瞬时探测抖动，但没有足够证据宣称根因已消失；任务6开始前必须再次检查。
- 当前受限 EvalOS 维护身份不能查看或删除宿主机上可能存在的惰性旧 Nginx 文本规则；实际签名入口已工作，旧规则没有参与 readiness。此项只能由既有 EvalOS 管理身份在后续维护窗口只读确认，不能绕过权限获取 root。
- EvalOS保留若干不可变历史发布作为审计与回滚记录；这不是活动兼容通道。后续可按统一保留策略清理，但本任务没有越权删除服务器历史。
- 尚未做 Chrome 页面端到端验收，产品经理已允许后续再做。
- 当前是开发期串行单槽，不是商用高并发或高可用。

## 6. 建议继续还是停止

按产品经理要求停止在任务5。任务6、7、8没有开始，也没有创建资格 Trial或启动 EvalOS Runner。

后续产品经理明确说“开干”后，先只读复核双产品报到和实验室空闲，再进入任务6的零模型外围冒烟；不得直接跳到正式计分。
