## 2. 实际修改

### LangGraph：让最终报告说清楚“依据是什么”

完整调查证据不删减。模型在原有最终报告阶段明确选出本次报告采用的假设；程序保存这些既有假设的支持证据、反证，以及已通过检查的建议引用，形成报告依据快照。不是把全部收集材料都当作根因依据，也不在 Evidence Gate 之后重新修改假设或根因。

建议引用不仅必须存在于本次调查，还要与建议针对的假设有关；修复建议不能只拿反证充当支持。保留原有建议自审、前提、风险和验证方式，不加入固定动作目录或地名黑名单。

引用有误时复用原有的一次报告修正机会；仍有误则标记引用失败、不伪造引用、不额外开启调查循环。已有根因判断与报告引用交付状态分开记录。API 与页面读取同一份持久化报告；历史报告没有引用资料就明确说明，不从全部证据猜补。

### Agent+Harness：验证已具备能力，不重复建设

核对既有最终报告引用、建议 Skill 自审、建议与问题及证据绑定、实验室标准证据标签保留和事件持久化测试。无关建议测试包含“宁德 MTU”“北京 AGV 无线遮挡”及一般化的不相关引用；不是靠拦截这两个地名。

这证明相应边界回归通过，不代表固定规则能够保证任意自然语言建议永远正确，也不代表同一模型自审等于独立专家背书。本轮没有修改其产品代码、Skill 或核心架构。

### EvalOS：准确接收，不替考生补答案

- 最终引用只取两套产品明确发布的引用列表；删除递归扫描任意 `id`、实验室回执和事实标签拼成引用的做法。

## 6. 版本登记的唯一准备入口（本地工具，不是新服务）

`npm run release:check` 只读核对当前三份公开配置是否相互一致；通过只代表登记完整，不代表产品在线或资格 Trial 已通过。已有架构检查复用此函数，后续发布验证会自动覆盖它。

`npm run release:prepare -- <已审核的公开版本材料.json>` 只输出待审修改，不写文件、不访问网络、不提交、不部署、不接触历史实验。确认后才应用到当前候选。材料是本次发布的输入，不是第四份长期配置或新事实源。

材料来源必须清楚：

- `candidate_ref`、`expected_source_revision`：本次批准的产品和完整提交号；不接受简称猜测。
- `deployment_attestation`：从受控只读发布状态、实际 Git/镜像等取得的既有格式部署证明；不能从 Manifest 复制生成。
- `discovery`：当前 V5 只读连接器实际采集的产品公开运行合同和摘要。新版本采集时，给连接器传入上述新部署证明，不传旧的 `declaredCandidateRuntime`。旧 EvalOS 实例可能仍携带旧部署登记，不能把其过期发现结果当新版本证明，也不能手改摘要凑一致。
- `public_resource_limits`、`public_resource_enforcement`、`resource_evidence_ref`：本版本产品实际公开的资源、执行方式与来源；不从旧冻结配置复制假装本次采集。变化就拒绝本命令，另审资源变更。
- `database_revision`：实际发布状态；变化就另审迁移，本命令不能批准或回滚数据库。

两个用途继续分开：只读发现观察新版本，执行连接器严格核验冻结版本。它们共用 V5 实现，不是两套协议或自动回退。准备命令也不替代开考时的签名在线证明、版本核验和分配后的准确 Trial 绑定。

测试包含两套产品逐一更新、其他产品完全不变、漏改三份配置、证明缺失或矛盾、资源/数据库变化、凭据拒收、旧合同仍可读但不可运行。删除的旧源文件可从基线 Git 历史恢复；没有删除历史报告、证据、账本或数据。
