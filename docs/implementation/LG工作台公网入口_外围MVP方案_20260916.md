**定位**：LG 是一套**独立的完整平台**（独立前端 + 独立后端），AH 是另一套。
两者都是"考生"，各自能连同一个 5G 数字孪生实验室；EvalOS 是"考场"。
所以两套系统各有各的公网入口，**不共用地址、不共用口令、不共用限流、不共用方案文档**。
本文只管 LG。AH 另出一份。

## 1. 目标与非目标

**目标**：让人用浏览器像用生产系统一样使用 LG 平台——看工作台、**发起故障根因调查**、
**做人工审批**、切租户。功能不打折。

**非目标（本 MVP 不做）**：
应用级登录失败锁定、宿主机第二层防火墙、AH 的入口、单点登录、审计报表。
都记在第 6 节，不进这一轮。

**外围架构原则**：轻薄、稳定、与 EvalOS 同构。配置只有一个 `server` 块、一个 `location`。

## 3. 配置（全部内容，就这些）

**http 层**，新建 `/etc/nginx/conf.d/opsmind-lg-limit.conf`：

```nginx
limit_req_zone $binary_remote_addr zone=opsmind_lg:10m rate=20r/s;
```

zone 名与 EvalOS 的 `opsmind_console` **不同**：两个考生的入口不共用配额，
否则一方使用会挤掉另一方，那是把两个本应独立可比的系统耦合起来了。

**站点**，新建 `/etc/nginx/sites-available/opsmind-lg`（软链到 `sites-enabled/`）：

```nginx
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name lg-114-55-40-170.sslip.io;

    ssl_certificate     /etc/nginx/ssl/opsmind-lg/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/opsmind-lg/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;

    location / {
        include /etc/nginx/opsmind-lg-access.conf;     # 总开关：空=开放，deny all;=关闭
        auth_basic "OpsMind LangGraph";
        auth_basic_user_file /etc/nginx/opsmind-lg.htpasswd;
        limit_req zone=opsmind_lg burst=50 nodelay;

        proxy_pass http://127.0.0.1:8081;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 5s;
        proxy_read_timeout 300s;
    }
}
```

**不开 80。** acme.sh 用 TLS-ALPN-01（EvalOS 实测 `Le_Webroot='alpn'`），签发与续期都只需要 443；
而 80 在大陆公网会被阿里云 ICP 拦截页替换，对浏览器也没用。
少一个端口、少一个 301 跳转块。代价：漏打 `https://` 会得到"连接被拒绝"，比撞备案页更好判断。

**和 EvalOS 的唯一结构差异**：EvalOS 留了三个免认证 location（relay、presence、judge），
产品机**一个都不需要**——relay 在产品机上是**出站**方向（产品 API 是本地 `127.0.0.1:8081`）。
所以这份配置在严格度上比现在跑着的 EvalOS 更高。

**写操作全部放行**：发起调查、审批、切租户都照常走。它们本来就在 LG 自己的登录
和权限校验后面（审批还有 `submitter ≠ approver` 职责分离、30 分钟申请有效期、
60 秒执行票据），不因为请求来自公网而失效。

## 4. 实施步骤（5 步，S1–S2 无公网暴露）

| 步 | 内容 | 暴露 | 回滚 |
|---|---|---|---|
| S1 | 装 nginx；放上面两份配置，但**先只 `listen 127.0.0.1:8443`**；机上 `curl` 自测 | 无 | `apt remove nginx` |
| S2 | 生成 `opsmind-lg.htpasswd`（口令与 EvalOS **不同**，不入 Git）；`opsmind-lg-access.conf` 先写 `deny all;` | 无 | 删文件 |
| S3 | 安全组加 443 `0.0.0.0/0`；nginx 切到 `listen 443` | 443 开但全拒 | **删安全组规则（秒级，最彻底）** |
| S4 | acme.sh 签证书（TLS-ALPN-01 需要公网能到 443，故必须在 S3 之后；签发时 acme.sh 独占 443） | 同上 | 同上 |
| S5 | 清空 `opsmind-lg-access.conf` → 开放；走第 5 节验收 | **真实暴露** | 写回 `deny all;` + reload（秒级） |

**同批必做（否则 11 月会坏）**：装续期 systemd timer，每天跑一次 renew 脚本
（acme.sh 自己判断续期窗口，未到就空跑，天然幂等），LG 与 EvalOS 用同一套做法。
EvalOS 现在**没有任何调度在续证书**，`2026-11-13` 到期，过期会打断 relay 进而打断链路③④——
这件事比本方案急，建议先做。

写给主机的脚本一律幂等；云助手调用一律经 `ca.sh`（重试复用同一 `ClientToken`，见 RUNBOOK 坑 6）。

## 5. MVP 验收（5 条，逐条留回执）

1. **不带口令** → `401` + `WWW-Authenticate`，且 LG 应用日志里**没有**这次请求
2. **带口令** → 工作台打开、能登录、看到真实租户数据
3. **完整平台可用** → 从浏览器**发起一次真实调查**并**完成一次人工审批**，
   在工作台上看到执行过程与结论（这是"不打折的平台"的验收点）
4. **总开关有效** → 写 `deny all;` 得 `403`；清空后恢复
5. **不碰评测** → 链路③④ `preflight` 仍 `ready: true`、`blockers: []`；
   四个线上提交号与生产标签不变

## 6. 明确不做，但要记住

1. **不要因为"LG 自己有登录"就撤掉 nginx 的 Basic 认证。**
   LG 与 AH 都**没有关掉** FastAPI 自带的 `/docs`、`/redoc`、`/openapi.json`；
   AH 更是把这三个显式写进了免鉴权白名单（`main.py:383` 的 `public_paths`）。
   撤掉 Basic 认证，等于把整套接口说明书（含发起调查、审批的参数结构）公开。
   本 MVP **不额外加 404 规则**——因为 `location /` 上的 Basic 认证已经把它们盖住了。
   轻薄的代价就是这条依赖必须写下来。
2. **应用级登录失败锁定缺失**：AH 与 LG 的认证端点都没有失败计数或锁定（已 grep 确认）。
   MVP 阶段靠 Basic 认证作为前置关卡。要撤 Basic 之前必须先补这个。属产品侧待办，要改 LG 代码。
3. **SSE 端点**（`GET /api/v1/investigations/{id}/events`，`text/event-stream`）
   当前前端没用。将来若启用，nginx 要给它单独加 `proxy_buffering off;`。
4. **宿主机第二层防火墙**：安全组是唯一边界。加固项，可后补。
5. **AH 的入口另议**，它和 LG 差别实质：
   - 前端 API 地址是**构建期写死**的（`client.ts:1`，缺省 `http://127.0.0.1:8000`），
     盘上那份 7 月 28 日的 `dist/` 直接端出去会去连用户自己的笔记本，且 https 页发 http 请求会被
     浏览器当混合内容拦掉 → **必须带 `VITE_AGENT_API` 重新构建**
   - AH 控制台的写入端点包含 **`/v2/admin/users`、`/v2/admin/roles`、
     `/v2/remediation/kill-switches`、`/v2/remediation/policy-packs`** —— 建账号、改熔断策略。
     LG 控制台没有这两类。所以"写操作是否全放行"这个问题，AH 的答案不一定等于 LG 的
6. **Git 里 `infra/nginx/opsmind-evalos.conf` 是 09-15 加认证之前的旧版**
   （仍写 `allow 111.55.79.0/24; deny all;`），按它部署会把 EvalOS 控制台重新锁死，要一起修。
7. **外部爬虫曾请求过账本里真实存在的 trial URL**，泄漏源至今未查清（HANDOFF 遗留第 3 条）。
   加口令后 URL 泄漏不等于数据泄漏，但那个渠道还在。
