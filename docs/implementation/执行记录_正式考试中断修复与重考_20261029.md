## 二、三条规则落成了什么

```
【以前】 答题途中快照 45 秒没回话 → 当成适配器故障 → 去取消 AH（AH 没有取消接口）
         → 隔离 5 分钟 → 判「考生产品可靠性失败」→ 停整个队列
【现在】 答题途中快照没回话 → 只记一笔「这一次现场快照没采到」，考生继续答
         判分用的最后一次快照 → 重试 3 次、间隔 10 秒
             → 仍失败：考生正常收尾、考场复位，记「实验室环境故障」，这一场自动重跑一次
```

**和交接写法不一样的一处（量过才改的）**：交接说「每次快照都重试 3 次」。实测 AH 每场调 38~69 次快照，
平时每次 3~11 秒；DNS 那题中位数 11.4 秒。每次都重试的话，一次卡住就是 155 秒，几次下来考生会被拖到超时，
反而算成考生的错。中途快照不参与判分（判分只读最后一次），所以中途只试一次。

**第③条附带拍板（10-29 下午问过产品经理）**：考生**自己的原因**没答完（报告被打回 3 次收口、熔断、程序报错）
= 这道题不通过、0 分、进分母；正式胜负照常出。考场原因的失败重跑一次仍失败 → 正式结论仍标「证据不完整」。

| 这一场怎么了 | 成绩单 | 正式胜负 | 请求状态 |
|---|---|---|---|
| 正常答完 | 按判分 | 参与配对 | — |
| 考生自己没答完 | 不通过，进分母；漏斗第一步「交卷」卡住 | 按 0 分参与配对，照常出结论 | 完成 |

## 三、执行中挖出来的四个问题

1. **实验「关闭」只认 COMPLETED**：一场失败 → 实验状态 FAILED → 永远盲态、AI 调查报 409。改为任一终态即关闭。
2. **请求状态**：原来只要有一场失败就标 FAILED，概览会显示「正式考试失败」。改为只在考场原因失败时才标 FAILED。
3. **AH 会话续签从 01:31 起一直失败**：续签服务钉死了旧镜像 `sha256:a28b99…`，AH 发版后旧镜像被清掉。
   8 小时会话到期后考场问 AH 就 401。用 AH 5cbe507 的续签安装脚本重新指向线上镜像 `sha256:8b3e1b26…`，已轮换成功。
   **以后 AH 每次发版都要重装续签**（ah-deploy.sh 还没做这一步，见第五节）。
4. **单场页冻结源码显示为 0**：源码只在发起 AI 调查时才挂到单场上，单场页没挂就说「这是测试替身」并禁用按钮。
   改为显示同一考生、同一提交号、同一产物摘要的已登记快照（只读）。已提交，**考完再装**。
