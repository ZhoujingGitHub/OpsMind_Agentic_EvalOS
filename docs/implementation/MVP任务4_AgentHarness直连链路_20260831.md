# MVP任务4：Agent+Harness 直连真实5G实验室

- 日期：2026-08-31
- 状态：已完成
- 范围：Agent+Harness 的外围部署、版本切换、两次真实直连调查和清场；未经过 EvalOS，未产生 EvalOS 成绩

## 产品经理结论

Agent+Harness OpsMind 已经能单独连接真实5G实验室，由官方 Claude Agent SDK 单 Agent 自主使用 DeepSeek、MCP、Skills、ToolSearch、原生工具和 Harness 完成真实调查。

第一次运行得出 `probable`，不是 Agent “偷懒停止”，而是它继续查 AMF 时被外围错误的资源票挡住。修复资源票后，第二次真实运行拿到了 AMF/gNB 相关进程、服务和端口证据，结论提升为 `confirmed`，随后实验室完成确定性复位。

这证明“Agent+Harness + 真实5G实验室”直连链已经跑通。它不代表 EvalOS 评测链已跑通，也不代表受限修复动作链已经在本次运行中验收。

## 1. 这一步要解决什么

- 收口 Agent 应用的运行用户、Secret 权限和容器监督；
- 让三角色凭据续期不依赖某个容器名字；
- 把日常版本切换限制为本产品固定的状态、切换和回滚命令；
- 让直连调查获得本次实验室租约对应的完整可调查资源，而不是空范围；
- 用真实模型、真实工具和真实5G故障完成调查并清场。

## 2. 实际改了什么

- Agent API 由现有 Docker Compose 单独监督，运行身份统一为非 root `opsmind:opsmind`；
- Secret 继续由 root 管理并只读挂载，运行用户只获得本服务所需读取权限；
- 三角色续期继续由独立 timer 负责，但读取固定配置，不再依赖 Agent 容器名字；
- 建立 Agent+Harness 专用受限发布器，只接受已批准的12位版本，应用切换不执行数据库升级或降级；
- 把协议实验室进程探查与当前物理租约、运行目标和资源范围绑定；
- 资源票明确包含本次5G实验室的13个资源、1个隔离环境和7个服务。它没有开放密码、宿主机管理权、EvalOS内部信息或故障答案；
- 保留高权限动作必须经过原有审批和动作安全的规则，没有把“能调查”偷换成“能任意修复”。

## 3. 哪些核心明确没动

- 官方 Claude Agent SDK 单 Agent 与自主停止时机；
- DeepSeek V4 Flash Thinking；
- MCP、21个 Skills、ToolSearch 和 SDK 原生工具；
- Harness、Evidence、报告交付、预算和动作安全；
- MySQL/Redis 业务语义、Relay 和三角色权限算法；
- 调查假设、工具选择、置信度和结论由 Agent 根据证据自主决定。

没有增加第二调查 Agent、固定节点图、固定工具顺序、固定调查轮数或 Case 答案特判。

## 5. 还剩什么风险

- 本次真实运行是调查链验收，没有执行受限修复，因此没有用真实故障验证“提案—审批—动作—验证—回滚”全链；核心能力和安全门保留，后续资格 Trial 只能在对应 Case 明确授权时验收。
- 调查验证了关键 AMF/gNB 进程、服务和端口证据，不等于穷举验证所有可能的数据面故障。
- 本任务未做 Chrome 页面端到端验收；产品经理已明确允许先收口外围，页面验收留到后续统一进行。
- 当前是开发期单机、串行实验室，不是商用高可用。
