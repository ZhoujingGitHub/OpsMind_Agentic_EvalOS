## 4. 主机和服务基线

- 共享产品主机上的 Agent API、LangGraph API/Worker、MySQL、PostgreSQL 和 Redis 当前都在运行；已有容器未因本任务中断。
- 主机开机标识已记录，用于后续验证断电重启后的租约隔离。
- 发现 LangGraph 存在一个已经删除了配置文件、但进程仍在运行的旧 systemd 监督进程。它和 Compose 同时管理同一组容器，是明确的“双重监督”风险。任务3必须先安全切换为一个唯一负责人，再清掉残留状态，不能直接强停。
- 还发现两个已无配置文件的旧 systemd 状态：旧凭据刷新失败项、旧开机证明残留项。它们不应继续作为活动兼容路径，须在对应任务中清除。
- Agent 与 LangGraph 现有 Candidate relay 仍在运行。在任务5的新通道验收前先保留，验收后一次性删除，不能长期双轨。

## 5. 已处理的保护性问题

### 本机管理 WireGuard 的“假持久化”

重启后服务虽然标为自动启动，但它引用的是一个已经删除的临时配置文件，因此隧道实际没有恢复。现已：

- 把配置迁到持久目录；
- 重新安装并启动同名受管服务；
- 验证服务为自动启动且正在运行；
- 验证只能执行固定管理查询的受限通道可用。

新增的安装脚本只读取本机私钥文件，不把私钥、Token 或密码写进源码、日志或文档。

### 共享产品主机磁盘已从危险状态恢复

主机磁盘一度只剩约 100 MB。已删除 103 个没有被任何当前容器使用、且可由 Git 重新构建的旧产品镜像，并清理无用构建缓存；没有删除数据库、备份、当前镜像或上一个回滚镜像。

处理后约有 23 GB 可用空间，所有当前容器继续运行。删除的只是可重建产物，不能把这次清理误写成业务数据删除。

## 6. 已冻结的安全边界

- 不输出、不复制、不写入仓库任何私钥、Token、数据库密码或候选身份密钥。
- 不给部署账号通用 shell 或全主机 Docker 权限。
- 不让产品状态、EvalOS 状态和5G实验室状态互相冒充权威事实源。
- 不修改两套 OpsMind、EvalOS 和5G实验室的核心架构。
- 不启用正式计分，不批量运行 Trial。

## 7. 任务1入口条件

任务1只在本地锁定最小外围合同和失败测试，不连接5G实验室。只有这些错误都能被稳定阻断，才进入任务2：抢占同一实验环境、租约或 Trial 不匹配、报到过期、伪造签名、重放、EvalOS 重启沿用旧 ready、数据库版本不兼容、回滚误碰数据库或另一产品，以及用 Token、耗时、调用量或费用影响成绩。
