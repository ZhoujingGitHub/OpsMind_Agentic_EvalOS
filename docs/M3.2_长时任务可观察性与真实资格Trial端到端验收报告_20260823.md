## 一、验收目标

本轮不是启动 480 次正式评测，而是验证正式评测前最容易被忽视的一件事：真实 5G 根因调查可能持续几十分钟，但操作人员不能面对一个没有反馈的页面干等。

验收同时覆盖：

- 标准 5G 根因调查的候选考生最长运行时间为 45 分钟；
- EvalOS 为评分、证据固化和清理预留 5 分钟，单个 Trial 总上限为 50 分钟；
- 页面每 5 秒无打扰刷新一次运行状态；
- 外部考生适配器每 30 秒记录一次存活心跳；
- 每 15 分钟形成一次阶段检查点，但检查点不是强制终止线；
- 区分“仍在线”“仍有实质进展”“疑似等待”和“疑似卡死”；
- 不展示或伪造 Agent 的隐式思维链，也不按日志数量评分；
- 真实失败原因能够如实归属，Trial 结束后完成考场清理与 Twin 复位。

## 七、最终收口结果

### 7.1 修复前发现的真实产品运行问题

第一轮请求 `eval-request_ec7abcb4c93a3ef1b28f` 在真实 Chrome 中启动后，首个 Trial `trial_13b20ff0350ffd214fcb` 运行 5 分 11 秒失败。新版 EvalOS 已经保留了真实错误，没有再显示成 `unknown`：

> Claude Code returned an error result: No conversation found with session ID

云上核验发现，候选容器使用只读根文件系统，但没有为 Claude Agent SDK 提供可写会话目录。第一次模型调用可以运行并返回 session ID；后续恢复调用找不到磁盘上的会话记录，因此失败。

这不是 Case 能力失败、EvalOS 超时或 Twin 故障。平台保留了原始失败证据，并将剩余 Trial 安全停止：未开考 Trial 直接取消，运行中 Trial 完成考生停止、Twin 复位和隔离释放。操作员取消明确记为 `OPERATOR_CANCELLED`，没有算到考生头上。

### 7.2 部署层修复

- 保持容器根文件系统只读；
- 单独挂载 `/srv/opsmind-agent-harness/data/claude-state` 到 `/home/opsmind/.claude`；
- 设置 `CLAUDE_CONFIG_DIR=/home/opsmind/.claude`；
- 启动时检查会话目录可写，不可写就拒绝启动，避免开考数分钟后才失败；
- 候选镜像补充 Claude Agent SDK 沙箱所需的 `bubblewrap` 和 `socat`；
- 安全门禁新增静态断言，防止后续删除会话挂载、启动检查或沙箱依赖。

修复后容器仍然是只读根文件系统、无额外 Linux capabilities、`no-new-privileges`，只有 Claude 会话目录和既有工作区可写。

### 7.4 第二层部署阈值问题

`trial_dffc37794c1f07e06592` 最终运行约 17 分 33 秒后失败，错误为：

`SDKStreamIdleError - Claude Agent SDK 响应流连续 180 秒没有新消息。`

这证明会话持久化已生效，但考生部署仍保留了3分钟内部流空闲阈值。复杂5G跨域调查可能在一次模型调用或证据汇总中超过3分钟，因此该值会在50分钟Trial总预算之前误伤真实调查。

处理方式：

- 安全停止仍使用旧配置的剩余Trial，不覆盖已有失败证据；
- 把考生部署层流空闲阈值调整为600秒，与页面“5分钟提醒、10分钟疑似卡住”的规则一致；
- 明确把 `investigation.heartbeat` 只算在线活动，不再冒充实质调查进展；
- 页面从公开审计事件中提炼当前动作、工具、公开摘要和下一步，不读取隐式思维链；
- 修复、加固并重新部署后，再创建全新不计分资格Trial。

本轮已有失败Trial保持原样。其中因180秒流空闲失败的Trial已完成Twin复位，结果为 `reset_ok=true`、`reset_clean=true`；安全停止后仍未自然终止的另一条Trial继续隔离，绝不冒充已清洁。最终签字等待隔离解除和新配置资格Trial收口后补充。

### 9.4 Agent+Harness 原生 Bash 沙箱的最小权限方案

真实调查已经证明 Claude Agent SDK 的原生 Bash 会进入 `bubblewrap` 沙箱。Docker 默认的 seccomp 与 AppArmor 会分别拦截创建隔离命名空间和挂载隔离根目录，因此不能简单把整个容器改为 `unconfined`。

本轮新增了两份最小权限策略：

- seccomp 仍以默认拒绝为基线，只额外允许 `clone`、`clone3`、`mount`、`pivot_root`、`umount2`、`unshare` 六个沙箱必需系统调用；
- AppArmor 保留 `/proc`、`/sys` 和敏感网络族等默认限制，只允许沙箱建立和销毁隔离根目录所需的挂载行为；
- 容器继续使用非 root 用户 `10002`、只读根文件系统、`cap_drop: ALL`、`no-new-privileges` 和隔离工作区。

在一次性、无网络、只读、无 Linux capability 的测试容器中，原生 Bash 已输出 `BWRAP_CUSTOM_POLICY_OK`，证明不需要关闭全部安全防护。

当前唯一未执行的生产变更，是把这两份策略持久安装到产品 ECS 并重建 Agent+Harness 容器。该动作会改变宿主机安全策略，必须取得用户明确批准后才能上线；在批准前，不得把一次性验证冒充云上正式资格通过。
