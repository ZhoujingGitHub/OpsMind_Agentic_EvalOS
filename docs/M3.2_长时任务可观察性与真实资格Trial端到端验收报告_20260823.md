本轮不是启动 480 次正式评测，而是验证正式评测前最容易被忽视的一件事：真实 5G 根因调查可能持续几十分钟，但操作人员不能面对一个没有反馈的页面干等。

### 7.4 第二层部署阈值问题

`trial_dffc37794c1f07e06592` 最终运行约 17 分 33 秒后失败，错误为：

`SDKStreamIdleError - Claude Agent SDK 响应流连续 180 秒没有新消息。`

处理方式：

- 安全停止仍使用旧配置的剩余Trial，不覆盖已有失败证据；
- 把考生部署层流空闲阈值调整为600秒，与页面“5分钟提醒、10分钟疑似卡住”的规则一致；

- 页面从公开审计事件中提炼当前动作、工具、公开摘要和下一步，不读取隐式思维链；
- 修复、加固并重新部署后，再创建全新不计分资格Trial。

### 9.4 Agent+Harness 原生 Bash 沙箱的最小权限方案

真实调查已经证明 Claude Agent SDK 的原生 Bash 会进入 `bubblewrap` 沙箱。Docker 默认的 seccomp 与 AppArmor 会分别拦截创建隔离命名空间和挂载隔离根目录，因此不能简单把整个容器改为 `unconfined`。

本轮新增了两份最小权限策略：

- seccomp 仍以默认拒绝为基线，只额外允许 `clone`、`clone3`、`mount`、`pivot_root`、`umount2`、`unshare` 六个沙箱必需系统调用；
- AppArmor 保留 `/proc`、`/sys` 和敏感网络族等默认限制，只允许沙箱建立和销毁隔离根目录所需的挂载行为；
- 容器继续使用非 root 用户 `10002`、只读根文件系统、`cap_drop: ALL`、`no-new-privileges` 和隔离工作区。

在一次性、无网络、只读、无 Linux capability 的测试容器中，原生 Bash 已输出 `BWRAP_CUSTOM_POLICY_OK`，证明不需要关闭全部安全防护。

### 10.2 发现并修复的 EvalOS 清场判断问题

真实运行还发现两项 EvalOS 自身问题：

1. Agent+Harness 对外复位接口 `/v2/investigations/{id}/protocol-lab/reset` 没有进入两层中继的精确白名单，导致考生侧清场调用被平台错误拦截；

- 独立复位不干净时仍立即停队列，不降低安全门槛；
- `ReportNotSubmitted` 明确归为考生能力失败，不冒充瞬态网络故障，也不自动重试。
