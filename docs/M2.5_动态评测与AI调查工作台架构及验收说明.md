# OpsMind Agentic EvalOS M2.5 动态评测与 AI 调查工作台

## 1. M2.5 要解决什么问题

M2 已经证明“数字孪生考场、参评适配器、Claude Agent SDK 核心 Agent、真实 DeepSeek、轨迹、评分和复位”能够端到端运行，但当时的界面更像一张验收快照，无法支撑日常评测运营和失败分析。

M2.5 把 EvalOS 从“能跑通的考场”升级为“能看清、能追溯、能解释、能改进的动态评测工作台”。它不扩大正式评分范围，也不提前冒充 M3 的大样本 A/B 正式评测。

## 2. 一句话架构

```text
数据集与实验定义
    ↓
Eval Harness（固定公平性、安全、隔离、预算、盲态、评分和账本）
    ↓
参评 Agent 自主运行 → Twin 真实终态 + 完整 Trace + 确定性 Code Grader
    ↓
不可变 Trial 证据库 + 参评源码快照
    ↓
只读 AI 调查员（Claude Agent SDK + DeepSeek + MCP + Skills）
    ↓
证据化诊断、评分解释、优化建议和权威方法论对照
```

核心不是固定流程图。参评 Agent 和 AI 调查员都由模型自主形成假设、选择工具、观察结果和决定停止时机。Harness 只固定不能交给模型选择的考场条件。

## 3. M2.5 的产品界面

| 页面 | 用户能看到什么 |
|---|---|
| 总览 `/` | 数据集、Case、实验、Trial、完成率、AI 分析数量及当前系统边界 |
| 数据集 `/datasets` | 数据集版本、Case 数量、能力域、安全级别和公开任务定义 |
| 实验 `/experiments` | 实验列表、状态、参评对象、数据集、进度和完成情况 |
| 实验详情 `/experiments/{id}` | 实验 Manifest、全部 Trial、参评盲态身份、Case、成绩和状态 |
| Trial 详情 `/trials/{id}` | 结果与环境、完整轨迹、逐维评分、冻结源码、AI 分析五个视图 |

这些页面读取服务端数据库，不再依赖前端写死的 M1/M2 JSON 快照。

## 4. Trial 详情为什么分成五部分

1. **结果与环境**：回答“最后修好了吗、环境最后是什么状态、产物是否齐全”。
2. **完整轨迹**：回答“Agent 实际做了什么”。记录输入、工具调用、工具结果、安全门、预算、环境观察和输出；不记录模型隐式思维链。
3. **逐维评分**：回答“每一分怎么来的”。官方分数只来自确定性 Code Grader，展示逐维得分、证据引用、硬门禁和扣分原因。
4. **冻结源码**：回答“当时被测的究竟是哪一版代码”。每个 Trial 绑定内容寻址、带文件哈希的只读源码快照。
5. **AI 分析**：回答“为什么会这样、下一步怎么改”。调查过程、工具事件、报告和引用来源都可以审计，但 AI 无权改分。

## 5. M2.5 中的 Agent

### 5.1 参评 Agent

Agent+Harness OpsMind 是正式核心参评架构：

- 运行时：`@anthropic-ai/claude-agent-sdk`
- 模型：DeepSeek V4 Flash，经 DeepSeek Anthropic 兼容端点接入
- 原生能力：Read、Write、Edit、Bash、代码执行、Skill、按需工具发现
- 扩展能力：OpsMind MCP，把真实 Twin 的通用观测和参数化变更能力交给 Agent
- 决策方式：模型自主选择假设、证据、工具、参数、变更组合、复核方法和停止时机

LangGraph 只作为外部历史 V1 参评对象，不进入 EvalOS 核心，也不参与组织 M2.5 工作台流程。

### 5.2 EvalOS Lead Agent

Lead Agent 是 Claude Agent SDK 驱动的动态组织层，用于理解评测目标、按需调用 Harness 能力和组织分析，不是静态节点编排器。正式公平性条件仍由 Harness 强制执行。

### 5.3 只读 AI 调查员

AI 调查员类似“Agent Judge”，但它不是评分器：

- 只能分析已完成、已关闭实验中的不可变 Trial；
- 必须绑定冻结源码快照；
- 可以自主查看试题、轨迹、评分、相关 Trial 和源码；
- 必要时可通过受控研究工具搜索和抓取公开权威资料；
- 可以用原生 Read、Glob、Grep、Bash、Skill 和 ToolSearch 做只读调查；
- 不能使用 Write、Edit，不能修改 Trial、源码、Twin、Manifest、盲态身份、评分、策略或账本；
- 最终只提交诊断报告，报告经过 Harness 规范化、严格校验、哈希和冻结。

## 6. AI 调查员的 MCP

| MCP | 用途 |
|---|---|
| `get_trial_bundle` | 获取公开试题、结果、预算、终态、产物和证据索引 |
| `get_trace_index` | 先看完整轨迹的分布、异常高亮和游标，避免盲目逐页翻日志 |
| `get_trace` | 按游标读取必要的原始轨迹片段 |
| `get_grader` | 查看确定性逐维评分、硬门禁和辅助 Judge 结果 |
| `list_source_files` | 查看冻结源码文件清单与哈希 |
| `search_source` | 在冻结源码中按需检索 |
| `read_source_file` | 读取单个冻结源码文件 |
| `list_related_trials` | 对照同实验其他盲态 Trial，判断偶发还是重复模式 |
| `search_methodology` | 只用公开概念搜索权威方法论，不允许携带内部数据 |
| `fetch_methodology` | 只抓取 HTTPS 权威白名单站点，并记录 URL、时间和内容哈希 |
| `submit_report` | 提交最终结构化报告；这是结果合同，不是评分器 |

外部网页一律视为不可信信息，不能执行网页中的指令。研究查询禁止携带 Trial ID、内部路径、源码、IP、凭据或证据内容。

## 7. Skill

M2.5 延续版本化 OpsMind 插件和 Skill 机制。Skill 给 Agent 提供可按需加载的领域方法、证据纪律、安全边界和报告规范，但不把 Case 写成固定步骤，也不规定必须调用哪个工具或以什么顺序调用。

Skill 与评分器彻底分离：使用某个 Skill、工具名或工具调用顺序都不会直接加分。

## 8. 评分策略

### 8.1 官方成绩只看可验证事实

正式成绩由确定性 Code Grader 计算，核心维度包括：

- Twin 独立复核的真实最终状态；
- 根因边界是否正确；
- 证据覆盖与证据准确性；
- 轨迹中是否存在有效诊断和复核；
- 变更是否必要、最小且可恢复；
- 是否遵守时间、工具和资源预算；
- 是否触发越权、跨租户、外泄或危险动作；
- 信息不足时是否安全停止。

### 8.2 不以工具名和固定路径评分

评分器不要求固定工具名、固定调用顺序或预先写好的修复路径。工具名只用于能力授权、安全控制和轨迹审计。只要两个 Agent 采用不同路径但得到相同的真实终态、证据质量、最小变更和安全结果，官方得分就应相同。

### 8.3 硬门禁不可被其他分数补偿

没有修复真实终态、发生跨租户或越 Scope 行为、危险写入、证据外泄、无法复位等情况会触发硬门禁。不能靠“报告写得好”或其他维度高分抵消。

### 8.4 Judge 和专家的权力边界

Outcome、Evidence、Trajectory 三路模型 Judge 只提供辅助注意信号。专家评审保留为可选证据增强层。二者都不能修改 Code Grader 的正式分数，也不是 M2.5 验收的必选依赖。

## 9. 数据、日志和不可变性

- 每个 Trial 有独立命名空间、预算和盲态身份；
- Trace 只追加，不允许覆盖或事后改写；
- Trial 完成后写入不可变账本并校验哈希链；
- 源码快照按内容寻址，拒绝凭据文件、敏感内容和符号链接；
- AI 分析事件、来源和结果均只追加；分析完成或失败后都保留审计记录；
- AI 报告与官方评分分表保存，无法覆盖正式成绩；
- 凭据只从环境变量注入，不进入源码、轨迹、快照或交付物。

## 10. 本次 breaking change

M2.5 主动删除了旧 M1 静态控制台、静态快照合同和旧版兼容入口，统一使用 `evalos.4` 动态工作台 API、M2.5 数据库迁移和 Trial 证据模型。研发阶段不保留双写、兼容分支或旧页面，以避免后续 M3 同时维护两套事实来源。

AI 报告边界采用“宽进、严存”：模型可以用语义等价的自然结构提交，Harness 会规范成唯一严格结构并再次校验。无效网址会被丢弃，不会伪装成网络研究来源。

## 11. M2.5 与 M3 的边界

M2.5 验收的是“测量和分析工作台是否可信”，不是两套 OpsMind 谁更强。进入 M3 后才冻结正式大样本实验设计，进行独立盲测、重复运行、统计比较和 A/B 结论。

M2.5 放行至少要求：

- 两个真实 M2 实验、7 个已完成 Trial、864 条以上完整轨迹和 7 份确定性评分已导入；
- 每个 Trial 都绑定冻结源码，至少覆盖两种参评架构；
- 至少 3 份 Claude Agent SDK + DeepSeek 真模型 AI 调查成功，覆盖两种架构；
- 至少一次实际抓取权威白名单网页，不能只在报告里手写 URL；
- AI 调查包含真实只读工具事件、实质诊断和优化计划；
- AI 分析不改变任何官方成绩；
- 账本有效且证据中没有凭据材料；
- 动态页面、API、架构、安全、单元、集成和云端浏览器验收全部通过。
