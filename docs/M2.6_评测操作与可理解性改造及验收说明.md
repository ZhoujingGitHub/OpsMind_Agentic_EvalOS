# M2.6 评测操作与可理解性改造及验收说明

## 1. 攸关目标

M2.6 解决两个真实操作者问题：第一，页面原先偏工程化，机器事件和英文术语难以理解；第二，Case 只能查看，不能由人选择后单个或批量重新评测。改造不改变 Agent 的智能内核，也不把求解过程写成固定工作流。

核心继续是 **Claude Agent SDK + DeepSeek V4 Flash + MCP + Skills + Harness**。Agent 自主决定假设、工具、操作路径和停止时机；Harness 继续独占种子、预算、隔离、安全门禁、盲态身份、评分、复位和不可变账本。

## 2. 人话化但不丢专业性

界面采用“中文主术语 + 英文辅助”的统一规则，例如：

| 页面术语 | 含义 |
|---|---|
| 评测题目（Case） | 一道独立的运维考试题 |
| 单次评测（Trial） | 某个参评 Agent 做这道题的一次完整运行 |
| 评测执行层（Harness） | 负责考场公平、安全、预算、复位和留证的基础设施 |
| 机器日志（Machine logs） | 原始事件流；中文解释只帮助阅读，不改写机器事实 |
| 新建评测（Create evaluation） | 为选中的 Case 明确本次评测目的，创建新实验和新 Trial |
| 按原配置重新评测（Rerun frozen evaluation） | 沿用原实验冻结的全部考生和公平条件，只选择要重跑的 Case |
| 仅重新评分（Regrade） | 不运行 Agent，只用冻结证据重算分数 |

每条机器日志同时显示中文事件名、英文辅助说明、原始事件码、生命周期、执行主体和原始 JSON。未知事件不会被丢弃，也不会被编造含义。“查看原始机器记录（Raw JSON）”采用独立展开控件，避免嵌套按钮造成点击无反应。

## 3. 新建评测与按原配置重新评测

两个入口承担不同职责，不能混在一起：

- **新建评测（Create evaluation）**：位于数据集与 Case 页面。操作者先单选或批量选择“评什么”，再选择“双系统公平对比”或“某一系统单系统回归”这一评测目的。平台据此绑定冻结考生版本，不要求操作者手工拼装原始 adapter ID。
- **按原配置重新评测（Rerun frozen evaluation）**：位于实验和 Trial 页面。平台自动保留原实验冻结的全部参评考生、版本、套件和公平条件，操作者只能选择“哪些 Case 要重跑”。如果要更换或减少考生，必须回到数据集页面新建评测。

两类入口都支持单选、批量选择、选择当前筛选结果和清空选择。选择 Case 只决定“考什么”；Agent 仍自主决定“怎么解决”，平台不会按 Case 写死修复路径或工具顺序。

提交前必须经过运行前检查（Preflight）：验证请求类型、评测目的、冻结数据和套件版本、Manifest 3.0、参评版本、Case 数、重复次数、预算、模型和数字孪生就绪状态，并明确本次运行是否影响正式成绩。按原配置重新评测如果缺少原实验任一冻结考生，会被接口直接拒绝。

评测请求进入异步任务中心。关闭页面不会中断任务；每个请求记录操作者、原因、模式、幂等键、进度和新实验。取消只作用于尚未开始的 Trial，已经运行的 Trial 会安全完成并复位。

任务完成后按 Case 和参评版本对比新旧分数、通过结论、耗时、工具次数、费用信息和安全硬门禁，并显示重复运行的稳定性。

## 4. 评分与证据边界

- 快速验证（Quick validation）和定向回归（Targeted regression）属于诊断实验，不进入正式分数和排行榜。
- 正式评测（Formal evaluation）必须遵守完整冻结套件和重复次数规则。
- 重新评测永远创建新实验和新 Trial；旧 Trial、旧分数、旧轨迹不覆盖。
- 仅重新评分只读取冻结终态、轨迹和用量，生成独立只追加记录；原官方分数不变。
- 工具名和固定工具顺序不计分。评分依据真实终态、根因、证据、变更质量和安全硬门禁，不把修复路径写死。

## 5. Breaking change

M2.6 只接受 Manifest 3.0。旧 Manifest 2.0 不做静默兼容，运行前检查会给出明确中文错误，避免用旧合同产生不可比较的新证据。

## 6. 验收门禁

1. 核心/API 自动化测试全部通过。
2. Claude Agent SDK、无静态图工作流、M2/M2.5/M2.6 架构门禁全部通过。
3. 安全、秘密扫描、认证、幂等、取消边界、冻结考生完整性和正式口径隔离全部通过。
4. 控制台 lint、服务端渲染测试与生产构建全部通过。
5. 真实浏览器完成新建单系统评测、按原配置双考生重跑、Case 选择、运行前检查、异步任务、新旧对比、Trial 深链、原始机器日志展开、仅重新评分和按 Case 聚合回归。
6. 云端采用新不可变发布目录；切换前备份数据库，失败时自动回滚旧发布；旧发布不删除。
