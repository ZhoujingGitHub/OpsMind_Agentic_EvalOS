# M1.5 可选专家盲审操作手册

## 一、功能定位

专家盲审是可选的证据增强层，不是 M1.5 工程验收、L1 v2 正式 Pilot 或合成基准排名的前置条件。没有专家时，平台照常运行 90 个正式 Trial，并以确定性 Code Grader 作为唯一官方评分来源。

Outcome、Evidence、Trajectory 三路模型 Judge 同样没有排名权，只生成辅助诊断和注意信号。专家结论可用于理解模型 Judge 偏差、发现坏题或增强交付证据，但不能覆盖或修改已落账的 Code Grader 分数。

## 二、何时使用

只有管理员明确需要时才创建专家任务，系统不会自动把每个 Trial 推入复核队列。建议优先选择：

- Code Grader 与模型 Judge 明显分歧的样本；
- 三路 Judge 互相分歧或置信度低的样本；
- 安全风险、坏题或坏评分器嫌疑样本；
- 最终报告中的代表成功、失败、Lucky Pass 和工具恢复轨迹；
- 需要增强客户或管理层证据可信度的样本。

## 三、角色与盲态

- **评测管理员**：核验专家身份与资质，选择样本并预分配任务；不能替专家作答。
- **领域盲审专家**：只看公开题面、去身份 Outcome、Span Trace 和环境终态；看不到架构、Code Grader、模型 Judge 和私有参考标签。
- **第三仲裁专家**：仅在前两人分歧且确有必要时介入。

## 四、操作顺序

1. 部署环境设置高强度 `EVALOS_API_TOKEN`。
2. 管理员显式选择 Trial，通过控制接口创建可选复核任务。
3. 核验专家身份和 5G/运维资质，登记 `qualification_ref` 与核验人。
4. 为每位专家创建独立凭据并预分配任务，禁止共享账户或自行挑样本。
5. 专家分别判断 `outcome`、`evidence`、`trajectory` 和 `safety_violation`，引用 Trial、Span 或 Evidence ID 并写明理由。
6. 两人完全一致时形成一致意见；分歧样本可选择第三人仲裁。所有决定只追加，不能覆盖或删除。

## 五、结果解释

专家样本足够时，平台可以计算模型 Judge 相对专家意见的混淆矩阵、准确率、敏感度、特异度和 Cohen’s κ。这些指标是“可选质量信号”：

- 通过不赋予模型 Judge 排名权；
- 未通过不阻塞正式 Pilot 或 Code Grader 排名；
- 样本不足只显示“可选专家样本不足”，不显示验收失败；
- 专家意见不能回写修改 Trial、Grader 或历史账本。

## 六、专家提交检查

- [ ] 我不知道 A/B 对应哪种架构。
- [ ] 我看不到 Code Grader、模型 Judge 和私有标签。
- [ ] 我没有与另一位专家讨论后再提交。
- [ ] 我引用了具体 Trial、Span 或 Evidence ID。
- [ ] 我分别判断 Outcome、Evidence、Trajectory 与 Safety。
- [ ] 信息不足时明确指出，而不是猜测。
- [ ] 我理解该结论是可选质量信号，不会直接改写官方评分。
