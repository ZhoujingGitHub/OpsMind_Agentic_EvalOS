# EvalOS 多维限制来源审计与科学校准方案

> 日期：2026-08-27  
> 范围：EvalOS 自身、Candidate Adapter 5、真实外部 Agent+Harness 与 LangGraph 的公开预算合同  
> 状态：开发期修正基线；容量 Trial 与正式 480 Trial 继续关闭

## 一、结论

当前正式冻结源中的金额、Token、模型调用、工具调用、时长、存储、重试和并发，绝大多数不是由当前两套真实 OpsMind 的有效 Trial 分布推导出来的。

它们主要来自 2026-08-17 的平台基线提交 `67fe0f9b`。后续发生过两次局部调整：

- 2026-08-24 将单 Trial `wallclock_ms/compute_ms` 从 5 分钟提高到 50 分钟；
- 2026-08-26 将 `output_tokens` 从 32768 提高到 65536，以容纳双模型候选。

仓库中没有与这些数值一一对应的真实付费模型价格表、当前版本有效 Trial 样本、联合预算包络、P95 置信区间或报告收尾增量测量。因此这些数值只能视为历史安全基线，不能继续包装成科学资格预算。

## 三、必须分开的四类边界

### 3.1 Candidate 调查预算

按架构分别冻结：有效调查时间、模型调用、工具调用、输入/输出 Token、结果字节和成本。

### 3.2 终态交付保留量

调查停止后仍允许完成正式报告、归档、公开终态和最终用量结算。调查工具耗尽不得关闭报告通道。

### 3.3 EvalOS 外层保险丝

只防止失控 Worker、无限账单、无限存储和无法清场，不作为 Candidate 能力及格线。

### 3.4 不可校准的安全与质量规则

隔离、盲身份、隐藏 Case、独立审批、生产写关闭、不可变账本、独立 reset、确定性 Grader 与 Evidence Gate 不因 Candidate 表现而放宽。

## 四、科学采样规则

1. Agent+Harness 与 LangGraph 分别建立预算分布，不共享同一个预算值。
2. Case 只按公开的难度与责任域分层，不按具体 Case、Seed、答案或固定解题路径定预算。
3. 每个 Trial 都必须有完整模型、工具、证据、报告和结算时间线。
4. 相同工具、目标、参数、时间窗、无新证据且无验证目的的重复才标记为无效循环。
5. 合理重试、修复前后验证、不同节点或不同时间窗的查询不得误判为循环。
6. Candidate 缺陷、EvalOS/Adapter 缺陷和 Twin/基础设施故障样本永久保留，但不混入“正常任务成本”。
7. 预算以完整 Trial 的联合包络验证，不能把每个维度各自取 P95 后假定整体仍有 95% 通过率。
8. 预算计算样本与最终验证样本分离；未参与计算的新 Trial 必须验证不会被意外截断。

## 五、版本化合同方向

新的可执行冻结合同必须满足：

- 每个 contestant 有自己的预算 Profile；
- Candidate 预算直接使用产品公开原生六维口径（有效时长、模型调用、工具调用、总 Token、微美元成本、结果字节），不再把输入/输出 Token 或 compute 等 EvalOS 历史字段伪装成产品原生上限；
- 每个 Profile 显式记录适用源码、镜像、模型组合、合同版本和校准证据；
- 每个维度标记 `enforced`、`observed_only` 或 `not_observable`；
- 调查预算、终态保留量和外层保险丝分开；
- 历史 Manifest 与历史 Trial 只读保留，不通过兼容分支继续执行；
- 新合同不引入固定工作流、固定工具顺序或按 Case 特判。

## 六、当前云端只读基线

- EvalOS 当前发布：`m31-20260827-a50f53b395`；尚未包含本地 `0a1f685` 和 `fe8cf7c` 两个后续修复。
- `/health`：账本有效；运行请求 0；运行 Trial 0；未清场 Trial 0；正式开关 `enabled=false`。
- 云端显示的 480 条 `QUEUED` Trial 属于冻结正式实验 `exp_b26e08a90873a4b7fbbb`，实验从未开始、没有对应运行请求，正式开关仍阻止执行。后续健康页应把“冻结模板”与“可执行排队任务”分开显示。
- 服务器磁盘约 40 GiB，已用 21 GiB，可用 17 GiB。
- 本机 `opsmind-twin` 长期身份当前被服务器关闭连接；不通过放宽安全组绕过，后续优先从 EvalOS 可信服务器身份核验 Twin。

## 七、执行门禁

在下列条件全部满足前，不启动新的校准 Trial：

1. EvalOS 证据冻结与失败 Trial 用量修复已经部署；
2. 新的分架构预算合同已经通过测试；
3. Agent+Harness 原生 1 USD 截断不再干扰校准；
4. 两套 Candidate 均能确认所接收的冻结预算和用量口径；
5. 模型/工具/报告阶段时间线足以识别无效循环；
6. Twin `active_trial=null`、无租约且 `clean=true`；
7. 用户明确批准第一批非计分校准 Trial 数量。

容量 Trial 与正式 480 Trial 不在本轮自动授权范围内。
