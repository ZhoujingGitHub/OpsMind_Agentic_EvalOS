# OpsMind Agentic EvalOS M3.1 三组生产级加固与验收记录

时间节点：2026-08-23

当前结论：三组研发改造、全量自动化验收和本机最新版本运行态验收已经完成；480 次正式 Trial 仍保持关闭。最新原子发布包已经生成，但云端部署与真实 Chrome 点击验收尚未签字：阿里云自动化临时凭证已经过期、专用 SSH 身份未被服务器接受，同时本机浏览器控制进程被 Windows 沙箱初始化异常阻塞。云端尚未执行任何变更。

## 一、这次升级坚持的边界

- EvalOS 仍然使用 Claude Agent SDK、DeepSeek、MCP、Skill 和原生工具构成开放式单 Agent。
- Agent 自己决定调查假设、工具选择、调用顺序和停止时机。
- Harness 只负责考务公平、安全、隔离、预算、审批裁判、证据记录和确定性评分，不规定 Agent 怎么解题。
- EvalOS 不在内部复制 Agent+Harness OpsMind 或 LangGraph OpsMind，也不代替考生调用其内部 MCP。
- 两套 OpsMind 代码库没有被修改。
- 工程测试替身只能出现在 ENGINEERING_TEST 通道，不能替换真实考生，也不能冒充真实付费模型调用。
- 正式 480 Trial 没有被启动。

## 二、第一组：真实考生协议、Twin 和语义评分

1. 真实考生合同升级到 Candidate Adapter 4.0 和 Product Run Binding 2.0。
2. 每个 Trial 获得独立、不可串用的 Twin 命名空间。
3. Twin 准备结果带有结构化回执、配置快照和摘要，不能只靠一句“准备成功”。
4. EvalOS 只向外部真实产品提交题目、冻结范围和考场信息；考生继续调用自己的 MCP。
5. 原始产品事件逐条保留，再翻译成 EvalOS 通用事件；翻译层不能编造缺失证据。
6. Grader 按终态、证据内容、授权、验证、回滚、安全边界和预算评分，不按工具名或固定调用顺序评分。

人话结论：第一组解决“考的是不是真实产品、两名考生拿到的是不是同一张卷、证据有没有被翻译层改坏、评分有没有偷偷要求固定解题路径”。

## 三、第二组：任务恢复、取消、租约和真实用量

1. 评测任务重启后会恢复排队和运行中的任务，不会因为服务重启整批丢失。
2. Runner 持续续租；租约过期会先留下不可变的 INTERRUPTED 尝试，再重新排队。
3. 安全停止会取消尚未开始的 Trial、通知正在运行的真实考生停止、等待终态、复位 Twin，并保留全部证据。
4. 如果真实考生没有退出，Twin 槽位会被隔离，队列停止，绝不会把脏环境交给下一名考生。
5. Token、工具调用和费用只显示考生公开接口真实提供的数据。没有提供就是未知，不再伪装成 0。
6. 超限的那一次消耗也计入预算，不能因为被拦截就从账上消失。

人话结论：第二组解决“服务断了能不能接着考、点停止会不会粗暴杀进程、脏考场会不会串给下一人、考生没报费用时平台会不会假装免费”。

## 四、第三组：失败归属、冻结重试、统计结论和健康监控

### 4.1 失败先分清是谁的问题

| 失败类型 | 算在谁头上 | 自动重试 |
|---|---|---|
| 操作员主动取消 | 操作员 | 否 |
| 预算超限 | 考生本次能力结果 | 否 |
| 跨租户、越权或安全失败 | 考生 | 否 |
| 工具不存在、输出合同错误、证据绑定失败 | 考生能力 | 否 |
| 真实考生超时、不能终止、隔离不释放 | 考生产品可靠性 | 否 |
| Twin 复位或考场清理失败 | EvalOS 平台 | 否，必须先修平台 |
| 明确的 429 限流 | 瞬态基础设施 | 按冻结合同 |
| 明确的连接重置 | 瞬态基础设施 | 按冻结合同 |
| 明确的服务暂时不可用 | 瞬态基础设施 | 按冻结合同 |
| 凭据、地址、版本或环境配置错误 | EvalOS 配置 | 否 |
| 无法证明是瞬态故障 | 未知 | 保守地不重试 |

只有事先写进实验 Manifest 的瞬态故障类型，才允许在冻结次数内自动重试。第一次失败尝试不会删除，重试成功也能看到原失败。

### 4.2 资格试跑不宣布胜负

- 快速验证和定向回归只有诊断权，没有正式排名权。
- 只有正式评测完成、所有配对 Trial 齐全、证据完整、考场清理完整，才可能进入正式结论。
- 两名考生按相同 Case、Seed 和重复编号组成配对样本。
- 使用按 Case 聚类的配对 Bootstrap 计算置信区间。
- 置信区间跨 0 时，只能说“现有证据不足以分出明确差异”。
- 证据缺失时，无论表面分差多大，都不能显示正式胜者。
- pass@k 表示多次中至少一次成功；pass^k 表示每次都成功，两者分开显示。

### 4.3 页面新增的信息

- 首页显示平台运行健康：运行中任务、未清理考场、用量未完整上报和账本完整性。
- Trial 页显示失败归属、是否允许重试、考场清理和隔离结果。
- 用量缺失显示“未提供”，不是 0。
- 评测任务页显示“本次能下什么结论”、有效 Trial 数、完整配对数、证据缺口、平均分差和置信区间。
- 停止按钮改为“安全停止任务”，点击前用人话说明影响并二次确认。
- 新术语使用中文主解释和英文辅助名称。
- 大批量任务的 Attempt 查询改成一次批量读取，避免运行健康页按 Trial 重复访问数据库。
- 统计报告按任务证据状态缓存，页面轮询不会反复计算 5000 次配对 Bootstrap；证据发生变化时自动生成新报告。

## 五、不可变证据

每次 Trial 继续保留独立命名空间、Append-only 轨迹、每一次 Attempt 的状态与清理结果、确定性 Code Grader 结果、任务结论摘要哈希，以及重试、取消、恢复和任务收口账本。

AI 调查员仍然只读，可以解释失败和提出优化建议，但不能改官方分数。

## 七、尚未签字的验收

真实 Chrome 自动点击验收尚未完成。当前阻塞是 Codex 的本机浏览器控制进程无法通过 Windows 沙箱初始化；同一时间 EvalOS 本机页面和 API 都可以正常打开。

云端最新版本部署也尚未执行。现有阿里云命令身份的 STS 临时凭证已经过期，EvalOS 专用 SSH 密钥当前未被服务器接受；公网 HTTP 入口仍能返回 Nginx 跳转，但 HTTPS 握手异常。为了避免在失去可靠回滚通道的情况下盲目改服务器，本轮到此为止没有对云端做任何变更。

因此，不能把“HTTP 页面可达和前端测试通过”冒充成“Chrome 所有按钮真实点击通过”。Chrome 通道恢复后，需要从首页开始逐项点击导航、数据集筛选、新建评测弹窗、实验行、Trial 页签、原始机器日志展开、评分器、AI 调查和评测任务详情，全部通过后才能签署最终端到端验收。
