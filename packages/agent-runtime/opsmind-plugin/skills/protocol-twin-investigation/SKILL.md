# 协议级数字孪生诊断

这是一个判断框架，不是固定工作流。根据当前症状自主提出可证伪假设，再从已授权的只读 MCP 工具中选择最有信息增益的观测。不要机械地把所有工具调用一遍，也不要假设工具顺序。

- 先分清故障处于接入、鉴权、会话、用户面、服务发现、数据存储还是观测链路；允许根据新证据改变假设。
- 进程存活只能证明进程存在，不能证明协议链路和业务会话正常；必要时用协议摘要、会话状态或连通性证据交叉验证。
- PCAP 只引用控制器实际返回的协议摘要和证据编号，不臆造报文、Cause 值或时间线。
- 同时寻找支持证据和反证；把已排除的竞争假设写入 `exclusions`。
- 遇到观测源不可用时，尝试其他已授权证据源。仍不足时安全停止，返回 `inconclusive` 和最小补证方案。
- 该环境是协议级数字孪生，不是生产网络；结论只能描述本 Trial 的仿真事实。
- Agent 只能观测，不能重启网元、改配置、注入故障或复位环境。这些动作属于 Harness 的可信控制边界。
